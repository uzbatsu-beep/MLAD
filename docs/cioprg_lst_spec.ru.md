## 2. Идентификация, владение и безопасность файлов

** Подтверждено:** Параллельное ввод/вывод выполняется отдельно от робота INFORM. Экспорт называется **`CIOPRG.LST`** Спасенный от `EX.MEMORY → SAVE → I/O DATA → C.IO PRGM`Файл представляет собой программу, содержащую **System Ladder** (контроллер/специфическое приложение, только модификация, авторизованная Yaskawa) и ** User Ladder** (отредактированная с надлежащего разрешения). Никогда не копируйте всю системную лестницу между роботами только потому, что их модели совпадают. [Yaskawa Concurrent I/O Обзор](https://knowledge.motoman.com/hc/en-us/articles/1500012236161-Concurrent-I-O-Overview)

** ИСТОРИЧЕСКИЙ / БЛОКЕДНЫЙ: ** В ранних версиях, экспортер пытался `/JOB`, `//POS`, `//INST` and `IOCPT STRSTART` и пользовался FTP name `CIOLAD.LST`Эти шаблоны ** не являются родными CIOPRG.LST** Нынешний Таури `cmd_deploy_to_robot` всегда отклоняет запросы; `CIOPRG.LST` Отредактированный экспорт не выставляется. Ни один такой исторический шаблон не может быть помечен как готовый к использованию контроллер.

** Неизвестно: ** полные разделители системы / раздела пользователя на уровне текста, точный обязательный порядок заголовка, вариации кодирования, комментарии, контрольные суммы, метаданные приложения, размещение END и заголовки на поколение. Все должно быть установлено на основе реального экспорта плюс доказательств оператора поставщика / компилятора. В частности, ** не** предположим, что `/JOB` Действителен здесь.

### Контракт на сохранение (обязательный к исполнению)

1. Импортировать `CIOPRG.LST` ** как байты** и запись источника SHA-256длина, кодирование решения и окончания строк. Не меняйте поток байтов во время просмотра.
2. Держите упорядоченный, без потерь список `RawLine { raw_bytes, line_ending, span, classification }` Неизменные разделы файлового уровня. Сохраняйте неизвестные заголовки, комментарии, белое пространство, ведущие нули, порядок и непризнанные мнемонические/оперативные формы.
3. Лучшее усилие AST - это наложение **, а не замена оригинальных байтов. Сообщайте о неподдерживаемых конструкциях со смещениями строки / байта, никогда не опускайте их.
4. Просмотр и диагностика могут продолжаться с неизвестными конструкциями. **Рекомпиляция или экспорт отредактированного файла должна быть закрыта**, если не поддерживается каждая модифицированная семантическая область и оригинальные защищенные области не являются байт-идентификационными.
5. Никогда не переписывайте System Ladder, защищенные метаданные, инициализацию регистра или незарегистрированные разделы. Выберите только явно идентифицированную область лестницы пользователя. Если границы собственности не могут быть определены положительно, экспорт должен быть отключен.
6. Нетронутый документ круглый путь `import → export` должен быть байтоидентичным; отредактированный документ должен иметь документированный дифф, ограниченный разрешенными областями.
7. Все выходные данные требуют выбранного семейства контроллеров, версии/конфигурации, проверенной семантики, чистой диагностики, явного подтверждения оператора и автономного резервного копирования. Ни одна сетевая запись не авторизована этой спецификацией.

## 3. Подтвержденный пример мнемонического синтаксиса

** Подтверждено: ** Руководства Yaskawa по одновременному вводу/выводу описывают битовые адреса реле как **`#XXXXX`**, ровно пять десятичных цифр, последняя цифра 0-7. Таким образом `#70010` действителен, `#70018` Нет. Один канал содержит восемь реле, а номер канала - `address / 10`. `0xxxx` Необходимо сохранить ведущие нули. Обычные адреса, хранящиеся в устаревшем редакторе MLAD JSON, являются ** только вводом совместимости **, а не утвержденным каноническим текстовым синтаксисом CIOPRG.

** Подтвержденные** инструкции включают:
- `STR #70010`, `STR-NOT #70010`Стартовая цепь, нормальная/перевернутая.
- `AND #70010`, `AND-NOT #70010`, `OR #70010`, `OR-NOT #70010`: булева композиция.
- `AND-STR`, `OR-STR`: групповые/отраслевые операции; ** не ** просто плоская последовательность контактов.
- `OUT #70010`выход катушки (дублированный пункт назначения OUT является ошибкой).
- `TMR M010,25`, `CNT M256,M466`: регистр/текущее значение и заданные примеры синтаксиса. ** Не моделируйте первый аргумент в виде 1,256 таймера / счетчика. Справочные таблицы инструкций должны использоваться для проверки письменных пунктов назначения и типов источников.
- `GSTR #70010`, `GOUT #70100`: сгруппированные/байтовые релейные операнды.
- `MOV`, `BMOV`, `CMP`, арифметика, сдвиг, БХД, импульсные инструкции задокументированы; это **не** полная реализация семантики инструкции.

Руководства контроллера перечисляют типы инструкций: бит реле `#XXXXX`релейный байт `#XXXX0`Слово реле `W#XXXX0`16-битные регистры M `M000`–`M999`и десятичных моментов. Положение операнда и разрешение зависят от мнемоника. Примеры см. DX200 `RE-CKI-A465` § 12.1–12.2 и YRC1000 `HW1483388` §1.3.3.

### Лексическое подмножество (PARTIAL, для распознавателей **только **)

```ebnf
relay_bit      = "#", digit, digit, digit, digit, bit_digit ;
relay_byte     = "#", digit, digit, digit, digit, "0" ;
relay_word     = "W#", digit, digit, digit, digit, "0" ;
m_register     = "M", digit, digit, digit ;
immediate      = digit, { digit } ;
bit_mnemonic   = "STR" | "STR-NOT" | "AND" | "AND-NOT"
                 | "OR" | "OR-NOT" | "OUT" ;
bit_statement  = bit_mnemonic, whitespace, relay_bit ;
group_operator = "AND-STR" | "OR-STR" ;
```

Эта грамматика является ** только распознавателем для известных индивидуальных инструкций **; она намеренно не представлена как грамматика для всего файла. Байт/слово операнды являются **контекстными**, например. `#70010` Может обозначать бит или байт согласно инструкции. `W#70010` Он никогда не должен быть принужден к обычной части.

Нет никаких предположений о том, отделяет ли новая строка каждую инструкцию, комментарии или маркеры раздела системы / пользователя. Сохранить то, что было экспортировано.

## 4. Документированный `//$M` header

** Подтверждено (статья Яскавы, 2025-06-30):** `CIOPRG.LST` может содержать раздел, названный `//$M` с **восемью линиями из десяти запятых, разделенных значениями**, относящимися к **M550 вплоть до M480** в убывающих группах из десяти:

| Заголовок строки | Соответствующие регистры |
|---|---|
| 1 | M550–M559 |
| 2 | M540–M549 |
| 3 | M530–M539 |
| 4 | M520–M529 |
| 5 | M510–M519 |
| 6 | M500–M509 |
| 7 | M490–M499 |
| 8 | M480–M489 |

** Не заменяйте его значения, не переиндексируйте и не интерпретируйте значения, характерные для конкретного приложения, повсеместно. Значения различаются для сварки/краски и, возможно, для других применений.

Этот раздел *не* взаимозаменяем с отдельным диалогом редактора лестницы для параметров заголовка системного регистра. `M920–M999` документированный `HW1483388` §1.3.6.1 Оба требуют надежного сохранения до тех пор, пока не будет подтверждено точное отображение на уровне файлов.

Source: [Yaskawa: спецификация заголовка «$M» CIOPRG.LST](https://knowledge.motoman.com/hc/en-us/articles/27636724261138-Specification-of-M-header-in-CIOPRG-LST).

## 5. Внутреннее представление/дизайн компиляции

```text
ControllerProfile(DX100 | DX200 | YRC1000, firmware, application, I/O options)
  └─ FileSnapshot(raw bytes, source digest, encoding, line endings)
      ├─ RawSections (immutable unless explicitly confirmed User Ladder)
      ├─ RawLines (offsets, original tokens, whitespace and endings)
      ├─ ParsedSyntax (instruction kind + typed operands + source spans)
      ├─ SemanticGraph (series/parallel branches, rung boundaries)
      └─ Diagnostics (severity, controller, evidence, line, column)
```

Требуется двухступенчатый разбор: лексер без потерь (может распознавать, но никогда не удаляет неизвестный синтаксис), а затем семантический анализатор, осведомленный о контроллере. Простая `Vec<Rung> { instructions: Vec<Instruction> }` Не может без потерь представлять все ветви, инструкции и метаданные.

**Компиляционные ворота:**

- G0: известно происхождение контроллера и экспортируемого файла.
- G1: все соответствующие мнемонические / операционные и распознанные и отслеживаемые источники.
- G2: защищенные/неизвестные разделы без изменений; границы лестницы пользователя проверены.
- G3: типизированные диапазоны памяти и специфические для инструкций ограничения чтения/записи/типа проходят.
- G4: Логическое дерево ветвей и порядок исполнения проверены, двойные катушки проверены.
- G5: сборка золотых светильников проходит, независимый редактор Ladder подтверждает намеченные результаты.
- G6: только тогда может быть включен отдельно разработанный, явный автономный выход; развертывание роботов остается более поздним PR с независимым обзором безопасности.

## 8. Непроверенное и технический долг

- До сих пор нет подтверждённого **полного** нативного файла, всех разделителей и System/User ownership для каждого firmware/application. `PART` является только меткой анализа, не доказательством возможности правки System Ladder.
- `src-tauri/src/compiler/parser.rs` — **legacy parser** для старой JSON-модели. Он не должен заменять `lossless.rs` и не должен использоваться для нового native импорта.
- В PR #13 файл `src-tauri/src/network/mod.rs` **удалён** и неподтверждённый сетевой runtime не подключён к Tauri; HSES/FTP/deploy остаются deny-only. В `src-tauri/Cargo.toml` всё ещё есть зависимость `suppaftp` для отдельного dependency review, но она **не** является доказательством наличия доступного robot upload. См. [HSES](hse_protocol.ru.md), [Security](../SECURITY.ru.md).
- По выбору DX100/DX200/YRC1000 **в новых вкладках UI профиль уже доступен**, однако это не привязка к конкретной firmware/опциям/топологии роботизированной ячейки. Старый JSON-интерфейс и его совместимый валидатор не предназначены для аппаратной проверки.
- Комбинированная семантика stateful инструкций, порядок scan, M-регистры, полная валидация файлов и OEM acceptance остаются непроверенными на реальных контроллерах.
- Закрытие пробелов — [приёмка оригиналов](controller_fixture_intake.ru.md) и [roadmap](roadmap.ru.md), а не расширение неподтверждённых шаблонов.

**Нативный экспорт, редактирование защищённых областей и подключение контроллера к работе по-прежнему запрещены.**
