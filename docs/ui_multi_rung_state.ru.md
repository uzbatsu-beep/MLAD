# Одновременное отображение цепей и OFFLINE тристейт-подсветка — объединённый PR #7

> **Статус и применимость:** документ описывает OFFLINE tri-state и UI-поведение PR #7/#8/#16/#17. Общее состояние `main` после [PR #29](https://github.com/uzbatsu-beep/MLAD/pull/29) и независимые уровни проверки см. в [project_status.md](project_status.ru.md). **Этот интерфейс не является live I/O и не показывает физическое состояние цепей безопасности.**

**Статус (18.11.2026):** PR #7/#8 объединены; PR #16/#17 добавили просмотр нескольких нативных цепей и независимое масштабирование. Основной предмет документа — **OFFLINE** визуальные состояния, **не** live I/O.

## Обнаруженные пользователем проблемы (Windows Bench v0.5.0-rc.1)

По пяти скриншотам:

- Графический редактор первоначально показывал только активную цепь, хотя были созданы две.
- Выбор контакта изменял зелёную рамку выделения, но **не** означал измеренное или смоделированное состояние TRUE/FALSE.
- TMR обрезался внутренней областью прокрутки; CNT не читался как цельный функциональный блок.
- GSTR/GOUT отображался одним символом без восьми отдельных индикаторов битов.

Это ошибки эргономики и отображения, **не доказательства связи с роботом**.

## Реализовано

### Общая область нескольких цепей

- Все цепи `*.graph.json` показываются в **одной вертикально прокручиваемой области** в порядке файла.
- Каждая сохраняет ID, адрес OUT, комментарий, выбираемые контакты и собственную метку результата выражения.
- Щелчок по контакту любой цепи делает её активной и открывает параметры. Добавление цепи **не скрывает** существующие.
- Общие ручные значения входов **не сбрасываются** при выборе другой цепи. Контакты с одним адресом в разных цепях получают одно и то же вручную установленное значение.
- Основной холст подстраивается под ширину. Сложные цепи прокручиваются горизонтально **внутри цепи**, без обрезания контактов.

### Трёхзначная окраска контактов и катушек (только OFFLINE)

| Состояние | Цвет | Смысл |
|---|---|---|
| TRUE | Зелёный | Контакт/булево выражение истинно при **вручную заданных** входах |
| FALSE | Красный | Контакт/булево выражение ложно при **вручную заданных** входах |
| UNKNOWN | Серый | Входных данных недостаточно для однозначного результата |

- Нормально разомкнутый контакт NO повторяет вручную установленный бит реле.
- Нормально замкнутый контакт NC **инвертирует** бит. Цвет относится к *проводимости логического контакта*, а не к исходному биту.
- Последовательное AND и параллельное OR вычисляются в трёхзначной логике. Например, `FALSE AND UNKNOWN = FALSE`; `TRUE OR UNKNOWN = TRUE`.
- Катушка окрашивается по результату **логического условия цепи**, а не по измеренному обратному сигналу физического выхода.
- При простом просмотре `CIOPRG.LST` без заданных тестовых входов цвета остаются нейтральными; live-состояния **не выдумываются**.
- Провода рисуются нейтрально-серыми: питание каждого участка при реальном scan не моделируется, и раскраска всей цепи ошибочно изображала бы подтверждённый поток сигнала.
- Состояния подписаны **текстом и цветом**; выбор узла помечается **отдельным жёлтым контуром** и не изменяет значение логики.

### Обзор и читаемость Advanced-блоков

- Панель Advanced показывает **каждый настроенный TMR / CNT / GSTR+GOUT** отдельной карточкой на одном общем прокручиваемом холсте.
- Высота SVG не сжимается по высоте grid-ячейки окна; внутренняя вертикальная прокрутка отключена, схема масштабируется по доступной ширине.
- У CNT явно видны **C (count)**, **R (reset)** и **Q**; у TMR — вход запуска, текущее значение/уставка и Q.
- Групповая передача показывает отдельные **b7...b0** с серыми/красными/зелёными индикаторами тестового значения и байт в шестнадцатеричной записи.
- Выход любого блока изначально **UNKNOWN**; только явный ручной офлайн-шаг даёт вычисленное состояние.
- Последний офлайн-образец хранится **по ID блока**, поэтому переключение между TMR и CNT не стирает его. Изменение блока делает старый образец недействительным.
- Групповой байт **не** выдаётся за один булев Q. Битовые значения выводятся только после ручного теста копирования байта.

## Безопасность и достоверность

**Критически важно:** отображаются **только вручную заданные** офлайн-сигналы и результаты детерминированных тестовых моделей. Это **не телеметрия DX100/DX200/YRC1000**. Удалённое подключение, HSES-monitoring, нативная запись CIOPRG и FTP-deployment отключены.

Цвета **нельзя** использовать как указатель safety-статуса или разрешение на движение. Изменённый `CIOPRG.LST` **не создаётся**.

## Тесты

Команды:
```bash
npm run test:graph
npm run test:advanced
npm run test:visual
npm run build

```

`visualState.test.ts` проверяет инверсию NO/NC, контакты и катушки, AND/OR с UNKNOWN-входами, ручное переключение входов и детерминированные ограничения. Прежние Rust/TypeScript-тесты моделей продолжают выполняться.

## Windows-приёмка пользователем

1. Создать минимум три цепи; убедиться, что **все одновременно видны**, а выбор одной не скрывает другие.
2. Для общего входа `#70010` последовательно задать `?`, `0`, `1`. Контакты NO на разных цепях должны синхронно стать серыми/красными/зелёными; NC инвертирует красный/зелёный.
3. Убедиться, что катушка повторяет результат условия, а ручные значения остаются при переключении цепей.
4. Добавить TMR, CNT, GSTR/GOUT; проверить видимость **всех трёх** и отсутствие обрезания C/R/Q на CNT.
5. Выполнить шаг TMR и CNT с изменением C/R; выбор другого блока не должен удалять последний собственный образец.
6. Проверить копирование 0x55: для b7..b0 видны чередующиеся ложные/истинные биты. Изменить источник и повторить шаг.
7. Изменить уставку TMR или адрес текущего значения CNT: старый результат именно изменённого блока должен стать UNKNOWN.
8. Проверить отсутствие HSES/FTP и любой возможности экспорта нативного `CIOPRG.LST`.

Ручные Windows GUI smoke-тесты **не являются частью статического CI**. Артефакты preview PR #7/#8 исторические, с ограниченным сроком хранения; для повторной проверки нужен актуальный Windows build. Скриншоты и обратная связь могут подтверждать **видимость** цепей, но **не поведение контроллера**.

## После PR #8: выбор и редактирование

- **Один щелчок** выбирает контакт или блок; цвет состояния определяется независимо от выделения.
- **Двойной щелчок / F2** по адресу **JSON-черновика** открывает inline-редактор: Enter — сохранить, Esc — отменить. Оригинальный `CIOPRG.LST` **редактировать нельзя**.
- В Advanced-блоке редактирование адреса или уставки сбрасывает старый ручной sample в UNKNOWN, а не оставляет устаревший зелёный.
- Подробные сценарии: [inline_address_editing.md](inline_address_editing.ru.md).
