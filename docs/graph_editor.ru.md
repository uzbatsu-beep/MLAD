# Графический редактор Ladder и визуализация — PR #4, интерфейс PR #7/#8

**Статус:** интерактивный **редактор графа в формате JSON** и независимое **семантическое отображение CIOPRG.LST только для чтения**.
Семейства контроллеров: DX100, DX200, YRC1000. **Это пока не совместимый с роботом редактор или экспортёр программ.**

## 1. Архитектурное разделение и безопасность

В приложении существуют четыре **разные рабочие области**, которые **нельзя смешивать**:

| Рабочая область | Исходный формат | Записывает файл? | Экспорт нативного CIOPRG.LST? | Команды роботу? |
|---|---|---|---|---|
| Graph Workspace (отдельная вкладка JSON, не основная) | `*.graph.json` (версия 1) | Да, **только JSON-черновик** | **Нет** | **Нет** |
| Advanced Workspace | `*.advanced.json` (версия 1) | Да, **только JSON-черновик** | **Нет** | **Нет** |
| Native Workspace (основная вкладка, только чтение) | Оригинал `CIOPRG.LST` | **Никогда** | **Нет** | **Нет** |
| Устаревший JSON-интерфейс | `project.json` (`Vec<Rung>`) | Да, только legacy JSON | **Нет** | **Нет** |

Непроверенный HSES-monitor отключён **как в UI, так и в Tauri backend**. Истинность одного реле не доказывает питание всей цепи; семантика настоящего scan и HSES требуют самостоятельной верификации.

Маркеры `PART 1` / `PART 2` и даже успешно построенный семантический граф **не доказывают**, что *System Ladder* можно безопасно редактировать. При импорте CIOPRG программа робота **не копируется** в редактируемый Graph Workspace.

## 2. Редактируемая модель `GraphDraft` v1

```json
{
  "version": 1,
  "controller": "YRC1000",
  "rungs": [{
    "id": "example-rung",
    "output": "#70020",
    "comment": "Demonstration only",
    "expression": {
      "kind": "or",
      "id": "join-1",
      "left": {"kind":"contact","id":"a","relay":"#20010","normallyClosed":false},
      "right":{"kind":"contact","id":"b","relay":"#70010","normallyClosed":true}
    }
  }]
}
```

- `kind=and` — последовательно включённые контакты; `kind=or` — параллельные ветви. Контакт может быть NO (нормально разомкнутый) или NC (нормально замкнутый).
- Выражение представлено **двоичным деревом**, а не плоским `Vec<Instruction>`.
- Устойчивые уникальные ID позволяют выбирать контакт и редактировать выражение без случайного изменения других узлов.
- Команды: добавить цепь, удалить цепь с подтверждением, выбрать контакт, вставить AND/OR-ветвь, переключить NC, редактировать адрес/катушку/комментарий, удалить контакт с подъёмом соседнего узла, Undo/Redo. Для крупных схем есть масштабирование и прокрутка.
- В `src/ladder/graphModel.ts` реализованы чистые иммутабельные обновления, преобразование AST и ограниченная детерминированная SVG-компоновка. `src/components/LadderCircuit.tsx` рисует последовательные/параллельные соединения и катушку. С PR #7 **все цепи** отображаются вместе; цвет контактов и катушек зависит от вручную заданных офлайн-значений `TRUE/FALSE/UNKNOWN`, **не** от физического питания. С PR #8 адреса контактов/OUT редактируются **двойным щелчком/F2** в JSON-схемах: Enter — сохранить, Esc — отменить. Inspector оригинального `CIOPRG.LST` **не** получает callback редактирования.
- Необязательный **автономный трёхзначный вычислитель условия**, явно помеченный OFFLINE, принимает вручную заданные 0/1/unknown; он **не** моделирует контроллерный scan, движение, безопасность робота и таймеры.
- Graph Workspace остаётся смонтированным при переключении на legacy-вкладку, поэтому само переключение не уничтожает несохранённые изменения.

## 3. Rust-валидация и сохранение черновиков

Модуль: `src-tauri/src/compiler/graph_draft.rs`.

Команды Tauri:

- `cmd_validate_graph_draft(project)`: классификация адресов для выбранного контроллера, проверка структуры, повторных катушек и обратной связи с собственным выходом.
- `cmd_save_graph_draft(filePath, project)`: сохранение **только** в `*.graph.json`, резервирование предыдущего файла через `*.bak` (общий механизм `.bak`) при перезаписи; `.LST` **никогда** не записывается. Некорректные *адреса* могут оставаться в черновике с диагностикой, но повреждённые по структуре или слишком большие проекты отклоняются.
- `cmd_load_graph_draft(filePath)`: открытие **только** `*.graph.json`, отказ для больших файлов, ошибок JSON, неподдерживаемой версии схемы и повреждённой структуры.

Ограничения версии 1: **128 цепей**, **4 096 узлов AST**, глубина **≤64**, размер файла **≤2 MiB**. SVG дополнительно ограничивает отображение до **256 элементов** и глубины **32**. **Это лимиты приложения, не пределы робот-контроллера.**

Legacy-команда сохранения не принимает `CIOPRG.LST` и отдельный формат `*.graph.json`: она работает только с обычными `*.json`. Backend-тесты проверяют разделение форматов даже при прямых IPC-вызовах. Существующие symlink-цели перед записью JSON отвергаются как дополнительная защита; права доступа ОС по-прежнему обязательны.

Валидатор адресов учитывает `DX100`, `DX200`, `YRC1000` согласно `docs/typed_memory_model.md`. Он предупреждает о self-feedback или катушках `SpecificInput`, выдаёт ошибки для некорректных и повторно назначенных выходных адресов.

В каждом ответе backend `edited_cioprg_export_allowed: false`. Успешная проверка JSON-черновика **не** является разрешением на выполнение или эксплуатацию.

## 4. Семантическая визуализация только для чтения

`SemanticPreview` после PR #3 также возвращает первые **4 096 узлов индексного выражения** и признак усечения. `CioprgInspector` конвертирует распознанные контакты/AND/OR из AST (до 256 узлов на отображаемую цепь) в тот же графический рендерер.

- Пользователь выбирает распознанную цепь; видит последовательные контакты, реальные ветвления схемы и катушку.
- Если узлы отсутствуют, глубина слишком велика, часть не поддерживается или исходник повреждён, UI **явно отказывает в визуализации**, а **не рисует выдуманную или неполную цепь**.
- Диагностика синтаксиса, перекрёстные ссылки, SHA-256 источника и исходный текст остаются доступны.
- Нативная визуализация не предоставляет элементов редактирования и **не создаёт** изменённый файл.

## 5. Проверка

- Rust-тесты модели GraphDraft: JSON round-trip, классы адресов по контроллеру, повторные катушки, стабильные ID, неверные адреса, ограничения структуры/узлов/глубины и self-feedback.
- TypeScript-тесты: геометрия AND/OR, инверсия NC, иммутабельные вставка/удаление, вложенные ветви, конвертация индексного AST и отказ при недопустимой компоновке.
- Существующие тесты lossless-чтения и семантической логики продолжают проверять побайтовую сохранность.
- `MLAD validation` в PR/`main` запускает `cargo test --locked`, `npm run test:graph`, `npm run test:advanced`, `npm run test:visual`, `npm run test:inline` и `npm run build`. **Это не ручной Windows GUI-тест.**

## 6. Краткое руководство оператора

1. Запустить MLAD и открыть вкладку **Графический редактор**. Это **отдельный JSON-проект**, а не редактируемая программа контроллера.
2. Выбрать семейство **DX100 / DX200 / YRC1000** и цепь в левом столбце. Щелчок по контакту в SVG выделяет его.
3. Использовать **+ Последовательно (AND)** для последовательного соединения либо **+ Параллельно (OR)** для параллельного. Без выделенного контакта команда оборачивает текущее выражение целиком.
4. Менять адрес контакта/OUT в свойствах либо **двойным щелчком/F2** непосредственно по подписи в **редактируемой** SVG-схеме. Enter — сохранить, Esc — отменить. Rust проверяет диапазоны контроллера, неверные и повторные назначения. Сложные выражения Advanced редактировать в редакторе условий, **не** заменять одним контактом.
5. `Undo/Redo` доступны через **↶ Отмена / ↷ Повтор**. Над **общим отображением всех цепей** установить вручную `? / 0 / 1`: контакты/катушки станут серыми/красными/зелёными. Робот **не опрашивается**. Для Advanced-блоков есть отдельные офлайн-тесты.
6. Сохранить проект под именем **`ladder.graph.json`** или любым `*.graph.json`; backend создаёт резерв предыдущей версии в `*.graph.json.bak` перед заменой.
7. Для просмотра копии реальной программы выбрать **Просмотр CIOPRG.LST**, профиль контроллера и путь к файлу. Выбрать распознанную цепь и посмотреть **неизменяемую** электротехническую визуализацию. При неподдерживаемом или обрезанном AST показывается предупреждение, а не догадка.
8. **Ни одна из операций не создаёт готовый для контроллера CIOPRG.LST и не загружает ничего в робот.**

## 7. Отложенные инженерные задачи

- Настоящие разрешённые примеры DX100, DX200, YRC1000 и golden fixtures для подтверждения принадлежности разделов и исполняемой семантики.
- Типизированное автономное **подмножество** `TMR`, `CNT`, `GSTR` и `GOUT` есть с PR #5; совпадение времени реального scan, прочие `BMOV`/арифметические функции и полная семантика не подтверждены.
- Нативный компилятор CIOPRG, подтверждённые System/User boundaries, разрешённая связь с роботом и процедура deployment.
- Достоверный HSES и live-диагностика по контроллерному scan; текущий редактор не выполняет мониторинг.
- Независимый round-trip через Ladder Editor 32 и безопасные стендовые испытания.

**Ни один промышленный контроллер, System Ladder или нативный файл робота не был изменён данным PR.**

## 9. Сохранение JSON после PR #29

Graph/Advanced/legacy JSON сохраняются через staging и резервную копию; конфликты выявляются по **байтам + File ID**, hardlinks отвергаются, проверяется SHA-256 staged-файла. Windows ADS/UNC/device paths запрещены. Это защита **отдельных JSON-файлов**, а не способ сделать графическим проектом CIOPRG-файл. [Модель угроз файловой системы](filesystem_security_pr29.ru.md): последнее окно check→rename, ACL, атомарная транзакция backup+target и восстановление после power-loss остаются **OPEN**. Портативный sidecar был только **условным предложением под названием PR #33** в [первоначальном плане](implementation_plan.ru.md), но фактический PR #33 позднее использован для переводов; sidecar **не реализован**.
