# Ladder Graph Editor & Visualization (альбом) PR #4 + интерфейсные изменения PR #7/#8

**Статус: ** интерактивный **JSON графический редактор ** + независимый **только для чтения CIOPRG.LST Семантическая визуализация*.
Целевые семьи: DX100, DX200, YRC1000** Это еще не робот-совместимый редактор/экспортёр.**

## 1.Разделение конструкции и безопасности

Проект имеет четыре различные поверхности. ** Они не должны смешиваться**:

| Surface | Формат источника | Файл мутантов? | Native CIOPRG.LST Экспорт? | Отправляет команды роботу? |
|---|---|---|---|---|
| Graph Workspace (отдельная вкладка JSON draft; не default) | `*.graph.json` (версия 1) | Да, только черновики JSON | **No** | **No** |
| Расширенное рабочее пространство | `*.advanced.json` (версия 1) | Да, только черновики JSON | **No** | **No** |
| Native Workspace (основная вкладка, read-only) | Original `CIOPRG.LST` | ** Никогда** | **No** | **No** |
| Наследие JSON интерфейс | `project.json` (`Vec<Rung>`) | Да, только наследие Джона | **No** | **No** |

Непроверенный HSES Монитор отключен ** как в видимом интерфейсе, так и в бэкэнд-команде Tauri **, потому что одно реле истинно не может установить состояние полной ступени; правильная семантика сканирования и HSES Проверка протокола остается отдельным рабочим потоком.

Neither `PART 1` / `PART 2` Маркеры и успешный семантический график подразумевают, что *Системная лестница* безопасно редактируется. Никакие существующие данные импорта CIOPRG никогда не копируются в редактируемое рабочее пространство.

## 2. Редакционная модель: `GraphDraft` v1

```json
{
  "version": 1,
  "controller": "YRC1000",
  "rungs": [{
    "id": "example-rung",
    "output": "#70020",
    "comment": "Demonstration only",
    "expression": {
      "kind": "or",
      "id": "join-1",
      "left": {"kind":"contact","id":"a","relay":"#20010","normallyClosed":false},
      "right":{"kind":"contact","id":"b","relay":"#70010","normallyClosed":true}
    }
  }]
}
```

- `kind=and` Серийные контакты; `kind=or` означает параллельные ветви. Контакт - это НЕТ или NC.
- Каждое выражение — бинарное дерево, а не сырая квартира. `Vec<Instruction>`.
- Стабильные уникальные идентификаторы поддерживают выбор контакта и редактирование выражения без случайных изменений в другом месте.
- Контроль: добавьте ранг, удалите ранг (подтверждение), выберите контакт, вставьте ветку AND/OR, переключите NC, отредактируйте адрес / катушку / комментарий, удалите контакт (раскрутите брата), отмените и переделайте. Zoom и Scroll поддерживают большие диаграммы.
- фронтенд `src/ladder/graphModel.ts` содержит чистые неизменяемые обновления, преобразование AST и ограниченный, детерминированный макет SVG. Производитель `src/components/LadderCircuit.tsx` отображает электрическую серию и параллельную проводку и катушку. С тех пор PR #7 Он показывает все ступени вместе и цвета контактов / катушек явным `TRUE/FALSE/UNKNOWN` Офлайн-тестовые значения, ** без реальных претензий со стороны государства**. С тех пор PR #8 Редактируемые диаграммы JSON поддерживают **double-click/F2** на контактных/OUT адресах, Enter для сохранения и Esc для отмены. Оригинал `CIOPRG.LST` Инспектор никогда не получает правки обратного вызова.
- Необязательный, четко обозначенный ** автономный трехзначный калькулятор условий** тестирует введенные пользователем 0/1/неизвестные контакты; он не имитирует состояние сканирования контроллера, движение, безопасность робота или таймеры.
- Графическое рабочее пространство остается установленным при переходе на унаследованную вкладку, поэтому несохраненные изменения не теряются при навигации по вкладкам.

## 3.Валидация ржавчины и обработка проектов файлов

Module: `src-tauri/src/compiler/graph_draft.rs`.

Таури командует:
- `cmd_validate_graph_draft(project)`: классифицировать реле сконфигурированного контроллера, проверить структуру и обнаружить дублирующие катушки и обратную связь.
- `cmd_save_graph_draft(filePath, project)`Спасти только как `*.graph.json`Делай лучшее усилие `.bak` копирование при замене существующего файла; ** никогда** `.LST`Недействительные *адреса* могут быть сохранены в проектах с диагностикой; структурно поврежденные или негабаритные проекты отклоняются.
- `cmd_load_graph_draft(filePath)`Читать только `*.graph.json`Отклонить негабаритные документы, искаженные JSON, неподдерживаемые версии схемы и сломанную структуру.

Пределы безопасности: версия 1, до 128 рангов, 4096 общих узлов AST, глубина ≤ 64, размер файла ≤2 MiB. Макет пользовательского интерфейса дополнительно ограничивает рендеринг выражения до 256 элементов и глубины 32. ** Это ограничения ресурсов приложений, а не ограничения роботов/контроллеров.

Командование спасения отвергает `CIOPRG.LST` и отдельной `*.graph.json` формат; ограничивается обычным `*.json` Файлы. Регрессионные тесты охватывают разделение формата даже для прямых вызовов IPC. Существующие цели симлинков отвергаются до того, как JSON пишет (глубокая защита; средства управления доступом к файловой системе ОС остаются необходимыми).

Адресный валидатор различает `DX100`, `DX200`, `YRC1000` согласно `docs/typed_memory_model.md`Предупреждает об обратной связи или `SpecificInput` Катушки и отчеты об ошибках для недействительных / дублирующих катушек.

Каждый ответ содержит `edited_cioprg_export_allowed: false`Успешная валидация проекта JSON не является разрешением на безопасность или исполнение.

## 4. Только для чтения семантическая визуализация

PR #3's `SemanticPreview` Теперь также возвращается первый **4096 индексированных узлов выражения ** и флаг усечения. Приложение `CioprgInspector` преобразует распознанные узлы AST-контакта/AND/OR (до 256 на отображаемую ступень) в рендерер электрической схемы *тем же*.

- Пользователь выбирает распознанную ступень; контакты и катушка нарисованы в порядке, включая истинную параллельную проводку.
- Если в семантическом графе отсутствуют узлы, слишком глубоко вложенные, неподдерживаемые или неправильно сформированные, пользовательский интерфейс показывает явный отказ, никогда не придуманный или частичный контур.
- Синтаксическая диагностика, перекрестные ссылки, источник SHA-256 Оригинальный текст остается в поле зрения инспектора.
- Ни один графовый элемент в инспекции CIOPRG не имеет возможности редактирования; ни один измененный файл не экспортируется.

## 6. Быстрый запуск оператора

1. Launch MLAD and open the **Графический редактор** tab. This is an independent JSON project, not an editable controller program.
2. Выберите семейство контроллеров **DX100 / DX200 / YRC1000** В левой колонке. Нажмите на контакт на диаграмме, чтобы выбрать его.
3. Use **+ Последовательно (AND)** for series contacts or **+ Параллельно (OR)** for parallel branches. If no contact is selected, these commands wrap the entire current expression.
4. Редактировать ретрансляционные адреса и OUT либо в полях свойств, либо **double-click/F2** на этикетке внутри редактируемого SVG; Вводить сохранения, Esc отменяет. Валидатор Rust проверяет выбранные диапазоны контроллеров и диагностирует недействительные или дублирующиеся адреса. Для сложных расширенных условий ввода используйте редактор выражения вместо того, чтобы заменять их одним контактом.
5. Use **↶ Отмена / ↷ Повтор** to navigate graph changes. Above the **combined view of all rungs**, set manual `? / 0 / 1` Входные данные для просмотра серых / красных / зеленых контактов и катушек; он никогда не читает робота. Продвинутые блоки имеют собственные независимые местные государственные тесты.
6. Сохранить файл с именем **`ladder.graph.json`** или любой `*.graph.json`; бэкэнд копирует предыдущий проект `*.graph.json.bak` Перед переписыванием.
7. To inspect a real robot backup, choose **Просмотр CIOPRG.LST** Выберите путь семейства и исходного файла. Выберите признанную ступеньку и просмотрите ее диаграмму электрического стиля **read-only**. Если AST не поддерживается или усечен, показана явная диагностика, а не угадываемая диаграмма.
8. ** Ни одна операция в этом рабочем процессе не создает контроллера CIOPRG.LST или загружает что-либо на робота.

## 7. Отложенные инженерные работы

- Реальные примеры и золотые светильники, экспортируемые DX100, DX200 and YRC1000 для подтверждения владения файловым уровнем и исполняемой семантики.

- Независимый редактор 32 круговых и безопасных лабораторных тестов.

** Никакой промышленный контроллер, системная лестница или файл робота не были изменены этим PR.
