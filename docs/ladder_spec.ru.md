# Лестница / CIOPRG.LST — архив предварительной спецификации

> **Исторический документ (навигационная отметка 18.11.2026):** нижеследующие выводы сохраняют дату первоначальной проверки, а не подменяют текущую реализацию. PR #1–#21 merged, Windows rc.9 опубликован. [Текущее состояние MLAD](project_status.ru.md).

Оригинальный прототип содержал сфабрикованный `/JOB`шаблон вывода в стиле и неполные примеры инструкций. Они ** не подтверждены в качестве исходного файла ввода/вывода Yaskawa Concurrent** и ** не должны экспортироваться или развертываться как CIOPRG.LST**.

Источник истины: **[CIOPRG.LST базовый уровень спецификации](cioprg_lst_spec.ru.md)**.

Текущие требования включают сохранение без потерь сырья, типизированные операнды, правильные `#XXXXX` and `W#XXXX0` синтаксис, специфическая для контроллера семантическая валидация, защита границ системы/пользователя и отказоустойчивый модифицированный экспорт.

Базовые документы, которые источники производителя устанавливают и отмечают неизвестный уровень грамматики файлов явно. Полная проверенная грамматика по-прежнему требует нетронутого экспорта реального контроллера для каждого поколения.

Смотрите также [Типовая модель памяти](typed_memory_model.ru.md) and [Исходный реестр](source_registry.ru.md).

## Состояние на 17.11.2026

С момента создания этого файла в `main` объединены read-only `lossless.rs`, `semantic.rs`, ограниченная native-инвентаризация TMR/CNT/GSTR/GOUT и два независимых JSON-редактора. Это не превращает прежний шаблон `/JOB` в правильную грамматику `CIOPRG.LST`. Для ввода адресов на графе используется [inline-редактирование](inline_address_editing.ru.md) **только в JSON**.

Источники и статус: [полная карта документации](README.ru.md), [базовая спецификация](cioprg_lst_spec.ru.md) и [архитектура](architecture.ru.md).
