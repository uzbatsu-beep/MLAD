# Семантический AST & Ladder Logic Analyzer PR #3, актуализация после PR #21

> **Статус и применимость:** этот документ описывает соответствующее функциональное подмножество и доказательства, собранные до/по PR #21; он **не** означает, что весь проект остановился на PR #21. Актуальный `main` после [PR #29](https://github.com/uzbatsu-beep/MLAD/pull/29) и независимые уровни CI/UserSmoke/OEM: [project_status.md](project_status.ru.md). Не выводить разрешение на native writer, HSES или исполнение скана из описанной здесь спецификации.

** Сфера деятельности (18.11.2026):** DX100, DX200, YRC1000 Concurrent I/O, **offline read-only** analysis of documented boolean mnemonics. Это **не** эмулятор контроллера, полный CIO-компилятор, инструмент авторизации оборудования или доказательство действительной редактируемой программы User Ladder.

- Yaskawa YRC1000 Параллельный I/O `RE-CKI-A467`, §12.2. [YRC1000 Параллельный I/O](https://www.scribd.com/document/573345245/Concurrent).
- Yaskawa [Конкурентный обзор I/O](https://knowledge.motoman.com/hc/en-us/articles/1500012236161-Concurrent-I-O-Overview), включая дублирующие ограничения на выход и возможное перекрытие BMOV/GOUT.
- Yaskawa [Картографирование конкретного I/O](https://knowledge.motoman.com/hc/en-us/articles/13086375717655-Mapping-of-Specific-I-O)Примеры лестницы пользователя/системы.

## 2.Архитектура

```text
LosslessDocument (PR #2: immutable bytes, original SHA-256, lines, lexical AST)
  -> semantic::analyze(document)
     -> indexed ExprNode array (flat, non-recursive)
        Contact {relay, inverted} | And {left, right} | Or {left, right}
     -> SemanticRung {output, root, first_line, output_line, inputs, section}
     -> Cross-references (#relays and M registers with source byte spans)
     -> Diagnostics + coverage flags
     -> Bounded semantic preview for read-only CIOPRG inspector
```

Оригинальный файл никогда не менялся и не переиздавался. Все ссылки на выражение являются ** целыми индексами в векторе плоского узла **; анализ, оценка, обнаружение и сериализация графика обратной связи позволяют избежать неограниченного рекурсивного прохождения AST.

## 3. Проверенное булевое подмножество и семантика стека

- `STR #A`Запустите контактное выражение; если предыдущее выражение находится в процессе, нажмите на промежуточный результат в стеке выражения.
- `STR-NOT #A`То же самое, с перевернутым контактом.
- `AND #B`, `AND-NOT #B`Булева связь с активным выражением.
- `OR #B`, `OR-NOT #B`Булева дизъюнкция с активным выражением.
- `AND-STR`, `OR-STR`Положите предыдущее промежуточное выражение и присоедините его к текущему выражению, используя И/ИЛИ. Недостающие выражения диагностируются как `UnbalancedBranch`.
- `OUT #C`Излучать ступеньку, только если есть активное и полностью сбалансированное выражение. Выход зависит от модели памяти, специфичной для контроллера; дубликаты записей помечаются на обоих устройствах. `PART` sections.
- `PART 1` / `PART 2`аннотировать заявленный раздел «Система/Пользователь»; `END`Закончите программу лестницы. ** Эти маркеры не доказывают безопасное право собственности на редактирование, совместимую грамматику файлов или правильное приложение/программное обеспечение.**

** Пример производителя — AND-STR:**

```text
STR #70010
OR #70011
STR #70020
OR #70021
AND-STR
OUT #70100
```

AST: `(#70010 OR #70011) AND (#70020 OR #70021)`.

** Пример производителя — OR-STR:**

```text
STR #70010
AND #70011
STR #70020
AND #70021
OR-STR
OUT #70100
```

AST: `(#70010 AND #70011) OR (#70020 AND #70021)`.

Это ** синтетические / иллюстративные тесты, воспроизводящие документированные примеры инструкций производителя **, а не фактические экспортированные файлы контроллера.

### Преднамеренный анализ барьеров

`TMR`, `CNT`, `GSTR`, `GOUT`и непризнанные инструкции ** могут иметь состояние, время, группу или побочные эффекты**, не представленные простым булевым выражением. Анализатор собирает ограниченные ссылки на регистр/группу, но ** отбрасывает любое непрогрессирующее булевое выражение** и добавляет диагностику при встрече с этими инструкциями. Последующие независимые `STR…OUT` Цепи можно анализировать. Ранг, непосредственно следующий за государственной операцией, не синтезируется из предшествующего контактного состояния.

То же самое относится к непризнанным директивам источника внутри открытого выражения, недействительным операндам и неподдерживаемым/непрозрачным линиям источника. Неподдерживаемые части сохраняются PR #2 Парсер без потерь.

## 4. Диагностика и статические проверки

| Code | Severity | Interpretation |
|---|---|---|
| MissingStart | Error | И/или без активного STR |
| UnbalancedBranch | Error | AND-STR / OR-STR без сохранения выражения |
| UnbalancedOutput | Error | Выйти без полного стек-сбалансированного выражения |
| Незавершенное / UnfinishedExpression | Error | END/EOF во время неполного цикла |
| DoubleCoil | Error | Одно и то же битовое реле имеет >1 OUT по распознанному коду, включая PART 1/2. |
| ReadOnlyCoil | Error | Категория выходного операнда не допускается консервативной моделью памяти |
| WriteNeedsReview | Warning | Специфический вход или другая зависящая от приложения запись |
| SelfFeedback | Warning | Ранг читает эстафету, которую он пишет; может быть преднамеренной защелкой |
| FeedbackCycle | Warning | Перекрестный цикл зависимости; может быть преднамеренной обратной связью |
| PossibleGroupOverlap | Warning | Выходящий байт может перекрывать отдельно распознанный выходящий бит |
| StatefulOpcode / GroupedOpcode / Непроверенный источник | Warning | Неизвестный семантический эффект; частичный подмножественный результат |
| PartOrder / PartOrder | Error/warning | Маркер раздела, несовместимый с выражением или ожидаемым порядком |
| AfterEnd | Error | Инструкция после окончания |
| NodeLimit / BranchDepthLimit | Warning | Охрана ресурсов анализатора превышена; **не** заявленный предел оборудования Yaskawa |

Частичные перекрестные ссылки доказывают, что нет конфликтующих авторов: GOUT / BMOV и неподдерживаемые инструкции также могут влиять на выходные биты.

## 5. Справочная модель

- `ContactRead` and `CoilWrite` принимаются только для признанных операндов битовых команд.
- `RegisterCurrentValue` and `RegisterSetpoint` Описательные для TMR/CNT; эффекты времени выполнения не моделируются.
- `PotentialGroupRead` and `PotentialGroupWrite` Признанный GSTR/GOUT. Слово «потенциал» является преднамеренным.
- Все сайты сохраняют исходную линию и пролет байта операнда. Каждое обозначение раздела явно является ** претензией ** на основе токенов PART, а не границей доверия.
- Каждая ступень также обеспечивает ограниченный, читаемый человеком предварительный просмотр выражения; индексированный граф выражения остается авторитетным.
- Граф зависимостей связывает действительные ранги, сопоставляя выходные реле с входными контактами. Сильно связанные компоненты обнаруживаются итеративным DFS (без рекурсивного стека вызовов); полученное предупреждение обратной связи является информативным, а не формальным доказательством тупика.

## 6. Оффлайновая оценка (не аппаратное моделирование)

`SemanticReport::evaluate_rung(i, signal_state_map)` оценивает индексируемое выражение по известным входным битам и возвратам:
- `Some(true)` / `Some(false)` когда это можно определить (включая краткосрочные результаты);
- `None` Когда вклады недостаточны.

Это оценивает только состояние, а не порядок сканирования робота, владение выходом, задержку ввода / вывода, семантику SET / RST, таймеры, счетчики или разрешение на выполнение. Функция не имеет сетевого доступа или эффектов записи.

## 7. Защитные ворота и ограничения

1. Оригинал `LosslessDocument` сырые байты и SHA-256 Неизменны; автор CIOPRG не добавлен.
2. `SemanticReport.edited_export_allowed` and `system_user_boundaries_verified` всегда `false`.
3. Зеленый `subset_analysis_complete` Флаг означает только то, что ** реализованное подмножество ** было проанализировано без ошибки. Он никогда не предоставляет экспорт или развертывание.
4. GOUT/BMOV, пишет M-регистр, порядок выполнения, статический анализ всего кода Системы/Пользователя и полная семантика инструкций, специфичных для контроллера, остаются неполными.
5. Ограничения на ресурсы (`MAX_BOOLEAN_NODES`, `MAX_OPEN_BRANCHES`) для стабильности анализатора, а не для проверенных пределов контроллера.
6. Ненастоящий DX100/DX200/YRC1000 Этот PR не претендует на то же поведение, что и настоящий Ladder Editor 32. Для будущей работы компилятора необходимы золотые крепления, аппаратная совместимость и полный авторизованный формат файла.

## 8. Испытания и приемка

Новый `src-tauri/src/compiler/semantic/tests.rs` включает в себя репрезентативные примеры для серийных/параллельных выражений, отрицательных контактов, вложенных стеков, отсутствующих STR, несбалансированных ветвей, двойных катушек через границы ЧАСТ, недействительных записей, само/взаимной обратной связи, барьеров неизвестного кода, сгруппированных выходных перекрытий, перекрестных эталонных промежутков, трехзначной оценки, защиты ресурсов и неизменяемых оригинальных байтов.

PR #3 уже слит в `main`. При дальнейшем изменении анализатора обязательны Rust regression tests, frontend checks и отдельное согласование нового PR. Старый текст о разрешении на слияние PR #3 более не является актуальным.
