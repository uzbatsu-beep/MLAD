# Семантический AST и анализатор логики Ladder — PR #3, актуализация после PR #21

> **Статус и применимость:** функциональное подмножество и доказательства относятся к разработке до PR #21; **не** означают, что весь проект завершился на PR #21. Состояние `main` после [PR #29](https://github.com/uzbatsu-beep/MLAD/pull/29) и независимые уровни CI/UserSmoke/OEM — [project_status.md](project_status.ru.md). Нельзя выводить разрешение на native writer, HSES или исполнение скана из этой спецификации.

**Область (18.11.2026):** DX100, DX200, YRC1000 Concurrent I/O; **автономный анализ только для чтения** документированных булевых мнемоник. Это **не** эмулятор контроллера, полный CIO-компилятор, инструмент аппаратного допуска или доказательство валидности редактируемой User Ladder-программы.

## 1. Источники и доказательная база

- Yaskawa DX200 Concurrent I/O `RE-CKI-A465`, §12.2.1–12.2.11: STR, STR-NOT, AND/OR, AND-STR/OR-STR, OUT, PART, END. [Руководство DX200](https://www.scribd.com/document/627793162/165294-1CD-DX200-OPTIONS-CONCURRENT-IO).
- Yaskawa YRC1000 Concurrent I/O `RE-CKI-A467`, §12.2. [YRC1000 Concurrent I/O](https://www.scribd.com/document/573345245/Concurrent).
- [Обзор Yaskawa Concurrent I/O](https://knowledge.motoman.com/hc/en-us/articles/1500012236161-Concurrent-I-O-Overview): ограничения повторного OUT и возможного перекрытия BMOV/GOUT.
- [Yaskawa Mapping of Specific I/O](https://knowledge.motoman.com/hc/en-us/articles/13086375717655-Mapping-of-Specific-I-O): примеры пользовательской и системной Ladder.
- DX100 Concurrent I/O `RE-CKI-A453`, [PDF производителя на образовательном зеркале](https://gab.wallawalla.edu/~ralph.stirling/classes/engr480/docs/Motoman/dx100_concurrent_io_155491-1CD.0.pdf).

## 2. Архитектура

```text
LosslessDocument (PR #2: immutable bytes, original SHA-256, lines, lexical AST)
  -> semantic::analyze(document)
     -> indexed ExprNode array (flat, non-recursive)
        Contact {relay, inverted} | And {left, right} | Or {left, right}
     -> SemanticRung {output, root, first_line, output_line, inputs, section}
     -> Cross-references (#relays and M registers with source byte spans)
     -> Diagnostics + coverage flags
     -> Bounded semantic preview for read-only CIOPRG inspector
```

Исходный файл **никогда не изменяется и не сериализуется заново**. Все ссылки между узлами выражения — **целочисленные индексы плоского вектора узлов**. Анализ, вычисление, поиск циклов обратной связи и сериализация не используют неограниченную рекурсию по AST.

## 3. Подтверждённое булево подмножество и стек выражений

- `STR #A`: начать выражение контакта; если предыдущее выражение не завершено, поместить промежуточный результат в стек.
- `STR-NOT #A`: аналогично, но инверсный контакт.
- `AND #B`, `AND-NOT #B`: логическое И с активным выражением.
- `OR #B`, `OR-NOT #B`: логическое ИЛИ с активным выражением.
- `AND-STR`, `OR-STR`: извлечь предыдущее промежуточное выражение из стека и соединить с текущим по AND/OR. Отсутствие необходимых выражений диагностируется как `UnbalancedBranch`.
- `OUT #C`: сформировать цепь только при наличии активного и **полностью сбалансированного** выражения. Выход проверяется по модели памяти выбранного контроллера; повторные записи диагностируются между обеими частями `PART`.
- `PART 1` / `PART 2`: пометить **предполагаемый** раздел System/User; `END`: конец Ladder-программы. **Маркеры не доказывают право редактирования, правильность общей файловой грамматики или соответствие firmware/приложению.**

**Пример производителя — AND-STR:**

```text
STR #70010
OR #70011
STR #70020
OR #70021
AND-STR
OUT #70100
```

AST: `(#70010 OR #70011) AND (#70020 OR #70021)`.

**Пример производителя — OR-STR:**

```text
STR #70010
AND #70011
STR #70020
AND #70021
OR-STR
OUT #70100
```

AST: `(#70010 AND #70011) OR (#70020 AND #70021)`.

Это **синтетические/иллюстративные испытания, повторяющие документированные примеры команд производителя**, а не экспортированные файлы реального контроллера.

### Намеренные барьеры анализа

`TMR`, `CNT`, `GSTR`, `GOUT` и неизвестные команды **могут влиять на состояние, время, группы или побочные эффекты**, которые невозможно выразить обычным булевым выражением. Анализатор собирает ограниченные ссылки на регистры/группы, но при встрече такой команды **сбрасывает незавершённое булево выражение** и добавляет диагностику. Следующие независимые `STR…OUT` цепи можно анализировать. Нельзя автоматически синтезировать цепь после stateful-команды из предшествующего условия контактов.

То же ограничение действует для неизвестных директив внутри активного выражения, некорректных операндов, unsupported/opaque строк. Базовый lossless-парсер PR #2 сохраняет их исходные байты.

## 4. Диагностика и статические проверки

| Код | Уровень | Значение |
|---|---|---|
| MissingStart | Error | AND/OR без активного STR |
| UnbalancedBranch | Error | AND-STR / OR-STR без сохранённого выражения |
| UnbalancedOutput | Error | OUT без полного сбалансированного выражения |
| UnfinishedAtEnd / UnfinishedExpression | Error | END/EOF при незавершённой цепи |
| DoubleCoil | Error | Один бит имеет больше одного OUT в распознанном коде, включая PART 1/2 |
| ReadOnlyCoil | Error | Класс выходного операнда запрещён консервативной моделью памяти |
| WriteNeedsReview | Warning | SpecificInput или другой зависящий от приложения вариант записи |
| SelfFeedback | Warning | Цепь считывает собственное выходное реле; может быть намеренной защёлкой |
| FeedbackCycle | Warning | Цикл зависимости между цепями; может быть намеренной обратной связью |
| PossibleGroupOverlap | Warning | Байт GOUT может пересекаться с отдельным распознанным OUT |
| StatefulOpcode / GroupedOpcode / UnverifiedSource | Warning | Неизвестный семантический эффект, частичный результат |
| PartInsideExpression / PartOrder | Error/warning | Маркер раздела внутри выражения или в неожиданном порядке |
| AfterEnd | Error | Инструкция после END |
| NodeLimit / BranchDepthLimit | Warning | Превышено защитное ограничение анализатора; это **не** заявленный аппаратный лимит Yaskawa |

Частичная таблица перекрёстных ссылок **не доказывает отсутствие других записывающих инструкций**: GOUT/BMOV и неподдерживаемые команды также могут влиять на выходные биты.

## 5. Модель ссылок

- `ContactRead` и `CoilWrite` допустимы только для распознанных битовых операндов.
- `RegisterCurrentValue` и `RegisterSetpoint` — описательные метки TMR/CNT; последствия исполнения **не** моделируются.
- `PotentialGroupRead` и `PotentialGroupWrite` относятся к распознанным GSTR/GOUT. Слово **Potential** здесь намеренно указывает на неподтверждённый эффект.
- Для каждой точки сохраняются строка и байтовый span операнда. Метка раздела — только **предположение** по токенам PART, а не граница доверия.
- Каждая цепь имеет ограниченный по размеру человекочитаемый предварительный просмотр выражения; истинным представлением остаётся индексный граф выражений.
- Граф зависимостей связывает распознанные цепи при совпадении выхода одной и контакта на входе другой. Сильно связные компоненты вычисляются итеративным DFS, без рекурсивного стека; предупреждение о feedback информативно и **не является доказательством deadlock**.

## 6. Автономное вычисление (не аппаратная симуляция)

`SemanticReport::evaluate_rung(i, signal_state_map)` вычисляет только индексное выражение из известных битов и возвращает:
- `Some(true)` / `Some(false)`, если результат определяется однозначно, включая случаи short-circuit;
- `None`, если входных значений недостаточно.

Вычисляется **только логическое условие**, а не порядок scan робота, права на выход, задержка I/O, SET/RST, таймеры, счётчики или разрешение на исполнение. У функции нет сетевого доступа и побочного эффекта записи.

## 7. Безопасность и ограничения

1. Исходные `LosslessDocument` байты и SHA-256 неизменяемы; CIOPRG writer не добавляется.
2. `SemanticReport.edited_export_allowed` и `system_user_boundaries_verified` всегда `false`.
3. Зелёный `subset_analysis_complete` означает только отсутствие ошибки **в реализованном подмножестве** и **никогда не разрешает** export/deployment.
4. GOUT/BMOV, запись M, порядок исполнения, анализ всей System/User Ladder и полная семантика контроллерных инструкций не реализованы.
5. `MAX_BOOLEAN_NODES`, `MAX_OPEN_BRANCHES` защищают устойчивость анализатора, **не** являются подтверждёнными лимитами робота.
6. Настоящие DX100/DX200/YRC1000 fixtures в PR #3 не импортировались; эквивалентность Ladder Editor 32 **не утверждается**. Для будущего компилятора необходимы golden fixtures, аппаратная проверка и полностью разрешённый файловый формат.

## 8. Тесты и критерии приёмки

`src-tauri/src/compiler/semantic/tests.rs` включает синтетические примеры последовательного/параллельного соединения, инверсных контактов, вложенных стеков, отсутствующего STR, несбалансированных ветвей, двойных катушек между PART, неправильных назначений, собственной/взаимной обратной связи, барьеров неизвестных команд, перекрытия групповых выходов, source spans, трёхзначного вычисления, ресурсных ограничений и неизменности оригинальных байтов.

PR #3 уже объединён с `main`. Любое дальнейшее изменение анализатора требует Rust regression tests, frontend-проверок и отдельного согласования нового PR. Старое описание условий слияния PR #3 утратило актуальность.
