Актуальный `main` после [PR #29](https://github.com/uzbatsu-beep/MLAD/pull/29) и уровни CI/UserSmoke/OEM отражены в [project_status.md](project_status.ru.md). Спецификация **не** разрешает native writer, HSES или исполнение скана на роботе.

**Статус (18.11.2026):** PR #8 объединён; изменение **самого адреса** разрешено **только в JSON-черновиках**. В Native Workspace после PR #16 двойной щелчок может менять лишь **локальный комментарий**, но **не адрес оригинального CIOPRG.LST или IONAME.DAT**.

## Сценарий работы пользователя

В **Graph Editor** либо отдельной вкладке черновика **TMR/CNT/GSTR/GOUT** дважды щёлкнуть по отображаемому адресу операнда (или сфокусировать выбираемый элемент диаграммы и нажать **F2**), чтобы изменить значение **на месте**.

- **Enter** — проверить синтаксис и записать новое значение в **отдельный JSON-черновик**.
- **Esc** или щелчок вне редактора — отменить изменение; сохраняется старое значение.
- **Некорректный ввод** — поле остаётся открытым с сообщением; проект не изменяется на этом шаге.
- **Одинарный щелчок** — сохраняет обычное поведение выделения.
- Изменение обычного контакта/OUT в Graph Workspace включается в историю **Undo/Redo**.
- Изменение Advanced-блока делает старую офлайн-пробу недействительной; до следующего ручного шага её результат возвращается к **UNKNOWN**.

### Редактируемые подписи

| Рабочая область | Поле | Формат |
|---|---|---|
| Graph editor | Адрес контакта NO/NC | `#XXXXX` (пять десятичных цифр, бит 0–7) |
| Graph editor | Катушка OUT | `#XXXXX` |
| TMR | Вход запуска (только простое условие из одного контакта) | `#XXXXX` |
| TMR | Регистр текущего значения | `M000..M559` |
| TMR | Уставка: число или M-регистр | `0..65535` либо `M000..M999` |
| TMR | Катушка OUT | `#XXXXX` |
| CNT | Count C / Reset R (только простые одно-контактные выражения) | `#XXXXX` |
| CNT | Current / preset / OUT | Как для TMR |
| GSTR/GOUT | Исходный и целевой байтовые адреса | `#XXXX0` (8 бит, начиная с бита 0) |

Сложные AND/OR-условия запуска, счёта и сброса редактируются **в отдельном редакторе дерева контактов** под схемой. Двойной щелчок **никогда** не должен заменять всё дерево одним битом.

## Проверка и безопасность

Frontend выполняет **ограниченную синтаксическую проверку** до изменения черновика. После этого редактор вызывает **контроллерозависимый Rust-валидатор**, который учитывает диапазоны и классы реле для выбранного DX100, DX200 или YRC1000. Текст адреса может пройти фронтенд, но оказаться недопустимым в данном поколении: следует устранить ошибку по Rust-диагностике.

Двойной щелчок **не даёт доступа к сети**. Изменённый JSON — не программа Yaskawa, не файл `*.LST` и не разрешение на запись/загрузку в робот.

В **Просмотр CIOPRG.LST** все схемы остаются **только для чтения**: ни Ladder SVG, ни Advanced SVG не получают callback редактирования. Байты исходной резервной копии и её SHA-256 не изменяются.

## Регрессионный сценарий Windows preview

1. Создать не менее двух графических цепей. Двойным щелчком выбрать NO, заменить `#20010` на `#70011`, нажать Enter. Должен измениться **только этот контакт**, выбранная цепь остаётся видна.
2. Нажать Undo, затем Redo, подтвердить оба перехода.
3. Дважды щёлкнуть по OUT, задать допустимый `#XXXXX` и подтвердить.
4. Ввести недопустимый индекс бита `#70018`: поле показывает ошибку, значение в проект **не записывается на этом шаге**.
5. Нажать Escape после редактирования контакта: старый адрес должен остаться.
6. Добавить TMR, дважды щёлкнуть по `M011`, уставке и OUT; проверить соответствующие поля. `M560` должен быть отклонён как current-регистр.
7. Добавить CNT; простые входы C и R должны изменяться независимо, **два порта сохраняются**.
8. Добавить GSTR/GOUT и изменить исходный/целевой байтовые адреса. Невыровненный `#20011` должен отклоняться.
9. Выполнить офлайн-тест, затем изменить операнд: предыдущее состояние блока возвращается к UNKNOWN, **не остаётся ложным зелёным**.
10. Открыть настоящий **образец-копию** `CIOPRG.LST` в Inspector; двойной щелчок **не** должен создавать поле ввода либо изменять native-файл.

Для резервных копий производителя **всегда использовать сохранённую копию**. Записывать модель, firmware, SHA-256 источника и кодировку. Не редактировать System Ladder действующего робота как часть такого теста.

## Известные ограничения и отложенные улучшения

- **На первом этапе проверяется только синтаксис.** Например, `#XXXXX` формально корректен, но класс или диапазон может быть запрещён для выбранного поколения. Rust после изменения возвращает диагностику; **черновик иногда может сохранить некорректный адрес**, чтобы пользователь его исправил. Успех frontend не означает допуск к оборудованию.
- Для **сложных** условий TMR/CNT из нескольких контактов редактировать дерево выражения в панели; inline-замена всего условия одним контактом запрещена.
- `Undo/Redo` реализован у Graph Workspace; полноценная отдельная история изменений `*.advanced.json` пока **не** реализована.
- Автотесты проверяют форматы, но поведение фокуса и double-click **в WebView2** требует ручного Windows smoke test.
- Семейство и конфигурацию контроллера проверяют отдельно; frontend-валидация **не** разрешает запись в реальный робот.
