## Пользовательский рабочий процесс

В вкладке **Graph Editor** или **TMR/CNT/GSTR/GOUT** дважды щелкните отображаемый операндный адрес (или сфокусируйте выбираемый элемент диаграммы и нажмите **F2**) для редактирования ** на месте**.

- **Enter** — проверка синтаксиса и сохранение нового значения для соответствующего независимого проекта JSON.
- **Esc** или нажмите снаружи — отмените изменения; исходное значение остается.
- ** Недействительный ввод ** — остается в редакторе с сообщением об ошибке; нет мутации проекта.
- ** Один клик** — сохраняет предыдущее поведение выбора.
- Редактирование обычного графового контакта/OUT участвует в существующей истории **Undo/Redo**.
- Редактирование расширенного блока делает недействительным предыдущий автономный образец блока, возвращая его дисплей в ** НЕЗНАМЕННО** до тех пор, пока не будет выполнен ручной этап тестирования.

### Редактируемые этикетки

| Workspace | Редактируемая этикетка | Format |
|---|---|---|
| Графический редактор | Контактное реле NO/NC | `#XXXXX` (пять десятичных цифр, бит 0-7) |
| Графический редактор | Вне катушки | `#XXXXX` |
| TMR | Начальный ввод (только для простого одноконтактного состояния) | `#XXXXX` |
| TMR | Текущий регистр | `M000..M559` |
| TMR | Пресет, буквальный или M регистр | `0..65535` or `M000..M999` |
| TMR | Вне катушки | `#XXXXX` |
| CNT | Count C / Reset R (только для простых одноконтактных выражений) | `#XXXXX` |
| CNT | Текущий регистр / Preset / Out | Как и TMR |
| GSTR/GOUT | Байт источника и байт назначения | `#XXXX0` (8 бит, начинающихся с бита 0) |

Более сложные выражения AND/OR start/count/reset продолжают редактироваться с помощью редактора контактного выражения ниже диаграммы; отображаемое выражение ** никогда** не заменяется одним реле двойным щелчком мыши.

## Проверка и безопасность

Frontend выполняет небольшую проверку синтаксиса, чтобы отклонить неправильные входные данные * до * изменения проекта. Существующий ** Руст-контроллер-специфический валидатор ** затем вызывается редактором для проверки юридических диапазонов и класса ретрансляции для DX100, DX200 or YRC1000Адрес, который проходит фронтальную валидацию синтаксиса, все еще может не пройти валидацию, специфичную для контроллера; для ее устранения должна использоваться диагностика Rust.

Двойной щелчок не имеет ** никакого доступа** к сети ввода/вывода. Отредактированный JSON не является программой Yaskawa, а не `*.LST` файл, а не разрешение на запись или развертывание робота.

In **Просмотр CIOPRG.LST**, все диаграммы остаются **только для чтения**: на диаграмме Ladder или Advanced SVG редактирование не предусмотрено. Источник оригинального байта и SHA-256 не изменяются.

## Контрольный список регрессии Windows Preview

1. С двумя или более графами, дважды щелкните один Нет контакта, измените `#20010` to `#70011`Нажмите Enter. Подтвердите только, что контакт изменяется и выбранная ступень остается видимой.
2. Нажмите Undo, затем Redo. Проверьте оба перехода.
3. Дважды щелкните этикетку OUT, введите действительный `#XXXXX` и подтвердить.
4. Введите недействительный индекс бита `#70018`Редактор должен показать встроенную ошибку без написания этого значения.
5. Нажмите Escape после редактирования контакта; исходное значение должно оставаться.
6. Добавьте TMR и дважды щелкните `M011`Предустановленные и выходящие этикетки. Проверьте соответствующие изменения полей. `M560` Он должен быть отклонен в качестве действующего реестра.
7. Добавить CNT и проверить простые C и R контактные адреса можно самостоятельно. Сохранить двухпортовую архитектуру.
8. Добавить GSTR/GOUT Редактировать адреса байта источника / назначения. неприсоединившийся `#20011` должны быть отклонены.
9. Проведите офлайн-тест, а затем измените соответствующий блок-операнд. Предыдущий результат должен вернуться в НЕЗНАМЕННОЕ; не должно быть показано несвежее зеленое состояние.
10. Открыть подлинный `CIOPRG.LST` в инспекторе. Двойной щелчок должен **не** создать поле ввода или изменить нативный файл.

Для резервных копий на основе поставщика ** всегда используйте сохраненную копию **. Рекордная модель, прошивка, источник SHA-256 и исходное кодирование; никогда не редактируйте системную лестницу на роботе в рамках этого теста.


## Известные ограничения и отложенные улучшения

- **Только синтаксис в первом шаге:** например `#XXXXX` может быть корректным текстом, но недопустимым классом или диапазоном в выбранном поколении; Rust-проверка после записи возвращает диагностику, но черновик может сохранить некорректный адрес для исправления.
- Для **сложных** условий TMR/CNT из нескольких контактов нужно редактировать дерево выражения в панели; инлайн-замена всего дерева одиночным контактом запрещена.
- `Undo/Redo` в текущей реализации есть у Graph Workspace; отдельная полноценная история изменений `*.advanced.json` пока не реализована.
- Автоматические тесты проверяют форматы, но реальную работу фокуса и double-click в WebView2 следует подтвердить ручным Windows smoke test.
- Контроллерный профиль нужно проверить отдельно: фронтенд-валидация не должна становиться основанием для записи в физический робот.
