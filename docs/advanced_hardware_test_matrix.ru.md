> **Важно:** это матрица **запланированных, не выполненных** OEM-испытаний. Ожидаемые значения — предположения по исходной документальной модели, **не измерения** на DX100/DX200/YRC1000. `OEMBench=NOT RUN`; HSES/FTP, native export и deployment — **BLOCKED**.

# MLAD — матрица стендовой проверки (DX100 / DX200 / YRC1000)

Применяется **раздельно** к **DX100**, **DX200** и **YRC1000**. Для каждого результата необходимы точные модель/firmware/application, ревизия Ladder Editor, SHA-256 резервной копии `CIOPRG.LST`, электрическая карта I/O, время сканирования и инженер, разрешивший испытание.

**Допуск по безопасности (редакция 18.11.2026, после PR #21):** текущий `main` MLAD **не** умеет экспортировать CIOPRG, загружать программы или управлять live I/O. Для испытаний использовать штатные OEM-средства правки/резервирования, изолированный неопасный стенд, независимую функциональную безопасность, исключение движения и регламент предприятия. Эта таблица **не заменяет** чек-лист OEM ввода в эксплуатацию. Запрещено использовать действующие safety-сигналы как тестовые точки.

## Примеры инструкций, подлежащих проверке

```text
; documentation examples ONLY, not a complete CIOPRG.LST
; TMR: one start condition, current M010, 100 x 100 ms = 10 s
STR #70010
TMR M010,100
OUT #70100

; CNT: two independent conditions, C then R, current M020
STR #70010
STR #70011
CNT M020,3
OUT #70110

; GRP: a pair of byte operations
GSTR #20010
GOUT #00010
```

Комментарии и фрагменты выше — только пояснения, **не** доказанный формат полного нативного файла с заголовками и разделами. Пока не подтверждены native-грамматика и границы System/User, стендовые программы следует готовить штатным **OEM Ladder Editor**, а не MLAD.

## Предварительные условия (обязательны до функциональных испытаний)

| Gate | Необходимое доказательство | Состояние |
|---|---|---|
| G-01 | Письменный допуск инженера, защищённая ячейка, оценка рисков, обученный оператор | Не подтверждено |
| G-02 | Зафиксированы модель робота, firmware и ID приложения | Не подтверждено |
| G-03 | Полная исходная резервная копия, её hash и проверенная процедура восстановления | Не подтверждено |
| G-04 | Тестовые сигналы **не** являются safety, motion, servo, guard или разрешениями движения | Не подтверждено |
| G-05 | Ladder создан/отредактирован допущенным OEM-инструментом; штатный parser принимает программу | Не подтверждено |
| G-06 | Независимо проверены электропроводка, мониторинг выходов и невозможность непредвиденного движения | Не подтверждено |
| G-07 | Назначены исполнители теста и восстановления; rollback проверен | Не подтверждено |

## Испытания TMR

| ID | Входы/настройка | Ожидаемое по документальной модели | Какие доказательства собрать |
|---|---|---|---|
| T-01 | Уставка=1, вход запуска OFF | Current=1, Q=OFF | Монитор M/Q |
| T-02 | Уставка=1, запуск ON ≥100ms | Current достигает 0, Q=ON | Осциллограмма времени |
| T-03 | Уставка=100, запуск ON <10s | Current>0, Q=OFF | Timestamp, число тактов |
| T-04 | Уставка=100, запуск ON ≥10s | Current=0, Q=ON | Время фронта Q |
| T-05 | Во время отсчёта перевести запуск OFF | Current перезагружен из уставки, Q=OFF | Чтение регистра |
| T-06 | После отработки таймера перевести запуск OFF | Q→OFF, Current перезагружен | Монитор Q |
| T-07 | Уставка из M-регистра | Current и Q согласно OEM-описанию | Оба M-регистра, firmware |
| T-08 | Изменить уставку в M-регистре во время отсчёта | **Установить экспериментально**, MLAD ничего не утверждает | Исходная последовательность, сканы |
| T-09 | Уставка=0 | **Измерить поведение контроллера**; автономная модель не является доказательством | Трасса M/Q |
| T-10 | Перезапуск питания при активном запуске | Подтвердить OEM-семантику сброса таймера | Стартовое состояние, timeline |

## Испытания CNT

| ID | Входы/настройка | Ожидаемое по документальной модели | Доказательство |
|---|---|---|---|
| C-01 | Уставка=3, R=ON | Current=3, Q=OFF | M/Q |
| C-02 | R=OFF, первый фронт C OFF→ON | Current=2, Q=OFF | Фронт C, M |
| C-03 | Удерживать C=ON несколько сканов | Повторного уменьшения нет | Трасса M |
| C-04 | Ещё два фронта C OFF→ON с падениями между ними | Current=0, Q=ON | Число фронтов, Q |
| C-05 | Дополнительные импульсы C после нуля | Current остаётся 0, Q остаётся ON | M/Q |
| C-06 | C и R становятся ON одновременно | Приоритет R: Current=3, Q=OFF | C,R,M,Q |
| C-07 | R=ON при удержании C=ON; затем R=OFF при C=ON | Не возникает искусственного дополнительного фронта C | Подробная трасса |
| C-08 | Сброс при Q=ON | Current перезагружается, Q=OFF | M/Q |
| C-09 | Уставка из M-регистра | Проверить заявленный диапазон, включая 65535 | Уставка/M/Q |
| C-10 | Перезапуск питания при активном C | Подтвердить поведение OEM-сброса | Стартовая трасса |

## Испытания GSTR/GOUT

| ID | Исходный байт | Ожидаемый байт назначения | Доказательство |
|---|---|---|---|
| B-01 | 0x00 | 0x00 | Исходный байт и все биты |
| B-02 | 0x01 | 0x01 | Порядок bit0 |
| B-03 | 0x55 | 0x55 | Чередующийся шаблон |
| B-04 | 0x80 | 0x80 | Порядок bit7 |
| B-05 | 0xFF | 0xFF | Все восемь бит |
| B-06 | Быстро менять исходный байт | **Измерить распространение/scan контроллера** | Оба потока байтов |
| B-07 | Непарный GSTR или GOUT при OEM-синтаксической проверке | Ошибка пары 4150 по руководству | OEM диагностика |
| B-08 | Байтовая группа GOUT пересекается с отдельным OUT | Отказ из-за повторного назначения | OEM диагностика 4040 |
| B-09 | Адрес начинается не с bit0, например `#20011` | Ошибка валидации операнда | OEM диагностика |
| B-10 | Адрес назначения read-only согласно карте контроллера | Отказ валидатора/конфигурации | Лог семейства/конфигурации |

## Негативные тесты ресурса, принадлежности и формата

| ID | Условие | Ожидаемое |
|---|---|---|
| N-01 | Регистр текущего TMR M560 | Отказ (необходимо M000–M559) |
| N-02 | Уставка CNT M999 | Синтаксически допустима по диапазону руководства, **но** фактическое назначение регистра проверить |
| N-03 | Константа 65536 | Отказ (максимум беззнакового 16-bit 65535) |
| N-04 | Два TMR/CNT используют один current M010 | Ошибка повторного регистра current (4100) |
| N-05 | Суммарно TMR/CNT/арифметических команд более 100 | OEM ошибка ресурса 4220; считать также существующий System Ladder |
| N-06 | Round-trip нативного файла при чтении | Исходные байты и SHA-256 `CIOPRG.LST` остаются идентичны |
| N-07 | Попытка сохранить `*.advanced.json` как `CIOPRG.LST` | Операция заблокирована |
| N-08 | Попытка HSES monitoring / FTP deployment | Операция заблокирована |

## Формат доказательств приёмки

Для каждого **фактически выполненного** случая записывать семейство, точную firmware, приложение/опции, ID, разрешённую конфигурацию, адреса источника/назначения, начальные регистры, временные отметки фронтов, **измеренные** M/Q, ожидаемые значения, PASS/FAIL, аномалии и доказательства восстановления. OEM-программы хранить приватно до обезличивания и разрешения на раскрытие.

**В GitHub нет подтверждённых результатов выполнения этих аппаратных испытаний.** Все случаи имеют состояние **NOT RUN**, пока не приложены независимый протокол, модель/firmware и измеренные значения. Локальный Rust/TypeScript CI и Windows build не равны OEMBench.

## Дополнительные UI-тесты и неизменность исходника (после PR #7/#8)

| ID | Действие | Ожидаемый результат |
|---|---|---|
| U-01 | Создать несколько цепей в `*.graph.json` | Все цепи показаны одновременно |
| U-02 | Вручную задать `? / 0 / 1` в Graph Workspace | Цвет NO/NC/OUT вычисляется локально; **не LIVE** |
| U-03 | Двойной щелчок по NO/NC/OUT в JSON | Меняется только JSON, Enter/Esc и Undo/Redo |
| U-04 | Двойной щелчок по M/preset TMR или CNT C/R | Меняется только `*.advanced.json`, прежний sample сброшен |
| U-05 | Заменить GSTR/GOUT `#20010` на `#20011` | UI отклоняет неверное байтовое выравнивание |
| U-06 | Двойной щелчок по native-адресу в `CIOPRG.LST` | Допустим лишь локальный комментарий, **не** изменение native |

UI-результаты документируются **отдельно** от аппаратных T/C/B/N кейсов. Правила приёмки и приватности: [controller_fixture_intake.md](controller_fixture_intake.ru.md).

## Дополнительные невыполненные аппаратные тесты после PR #21

| ID | Изолированный стендовый сценарий | Подтверждаемая величина |
|---|---|---|
| EN-01 | MOV/ADD/SUB/SHL/SHR при EN=0/1 | Запись назначения D и флаги при сканировании |
| MOV-01 | Значения 255/256/257 для byte и word | Усечение/Carry на границе 256 |
| SHIFT-01 | n=0/1/8/15/16 | Carry и последний вытесненный бит |
| SCAN-01 | Две инструкции, влияющие на `#51400/#51401/#51402` | Очерёдность сброса/обновления по сканам |
| GEN-01 | DX100/DX200/YRC1000 с разными firmware | Различия поколений |

**Все эти случаи NOT RUN**, независимо от успешного CI и автономной reference-модели. [Подробнее](oem_5_opcode_analysis.ru.md).
