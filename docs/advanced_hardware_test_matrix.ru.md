# MLAD — Hardware Bench Validation MatrixDX100 / DX200 / YRC1000)

Применяется отдельно к **DX100**, **DX200** и **YRC1000** Каждый результат должен записывать точную модель/программное обеспечение/приложение, редакцию Ladder Editor, `CIOPRG.LST` backup SHA-256, электрическое отображение ввода-вывода, время сканирования и инженер, который санкционировал испытание.

**Safety / setup gate (актуализация 18.11.2026, после PR #21** Экспорт, развертывание или контроль ввода/вывода MLAD CIOPRG в настоящее время отсутствуют. `main`Используйте поддерживаемое производителем редактирование / резервное копирование, изолированную неопасную испытательную установку, независимую функциональную безопасность, физическое ингибирование движения и процедуру тестирования сайта. Никогда не заменяйте эту матрицу контрольным списком ввода в эксплуатацию OEM-производителей или используйте сигналы, связанные с безопасностью производства, в качестве контрольных точек.

## Справочные инструкции в ходе испытания

```text
; documentation examples ONLY, not a complete CIOPRG.LST
; TMR: one start condition, current M010, 100 x 100 ms = 10 s
STR #70010
TMR M010,100
OUT #70100

; CNT: two independent conditions, C then R, current M020
STR #70010
STR #70011
CNT M020,3
OUT #70110

; GRP: a pair of byte operations
GSTR #20010
GOUT #00010
```

Комментарии и фрагменты выше являются пояснительными, * * не * * проверенный контроллер-нативный заголовок файла / макет секции. Только OEM Ladder Editor может использоваться для подготовки программ тестирования контроллеров до тех пор, пока не будут проверены все нативные форматы и границы системы/пользователя.

## Формат доказательства принятия

Для каждого завершенного случая, семейство контроллеров захвата, точная прошивка, параметры приложения / установки, идентификатор случая, утвержденная конфигурация теста, адреса источника и назначения, начальное состояние регистра, временные метки края ввода, фактические контролируемые значения регистра / выхода, ожидаемый результат, проход / сбой, аномалии и доказательства восстановления. Храните любую OEM-программу в частном порядке, пока не будет завершена санация и одобрение.

**В репозитории нет опубликованных результатов выполнения этих аппаратных тестов.** Кейсы считаются **неподтверждёнными**, пока не приложены стендовый протокол, точный model/firmware и измеренные значения. Локальные тесты MLAD/CI не засчитываются за аппаратное исполнение.
