# MLAD Preview rc.4 — all Ladder rungs, advanced zoom and IONAME annotations

> **Archived release note — navigation addendum from 18.11.2026.** Below are the details of the specific release **rc.4** published earlier; they do not describe the current release. `main`. Now. The release tag and the source archive of the previous version are not changed by this addition.

Status: OFFLINE / Read-only native source, Windows x64 bench preview.

## Improvements

- The Ladder tab renders **all rungs returned by the current bounded Semantic AST preview** as individual cards, instead of one selected rung.
- All recognized TMR, CNT and GSTR/GOUT preview cards support independent zoom − / + / 100%, without changing editor data.
- New read-only import for a local copy of `IONAME.DAT`. Entries follow the observed Yaskawa `/IONAME` header and sequential names in four comma-separated slots per row, segmented by directives such as `//IN` and `//OUT`.
- Unknown/invalid source formats are diagnosed rather than silently interpreted as known. Byte-exact SHA-256 reported and original IONAME.DAT never rewritten.
- Double-click a native Ladder **rung heading**, **contact/coil address**, **advanced-block operand** or **IONAME name** to edit **local MLAD comments only**. Enter saves, Esc cancels. Remarks persist in app local storage **keyed to the current CIOPRG source SHA-256**. Clearing the app profile/storage can remove them.
- Imported IONAME entries are **not automatically mapped** to numeric `#XXXXX` CIO relay addresses. The mapping depends on controller configuration; use an explicit manual association button for provisional local display.
- Original CIOPRG.LST, IONAME.DAT, FTP/HSES, native writer, live I/O and controller uploads stay **disabled**.

## Testing

1. Open a copy of CIOPRG.LST; verify Ladder displays all **available** supported chains, their source spans, and per-card comments.
2. Test zoom controls in Ladder and TMR/CNT/GSTR separately.
3. Double-click a rung title or address, enter a comment, save, and switch tabs. Check the comment is preserved after restarting the app (same source bytes/hash).
4. Load IONAME.DAT from a **copy**, compare its section/slot arrangement and names against the robot pendant/OEM editor. Current parser accepts only supported four-slot record layouts; unsupported or proprietary layouts may not be shown accurately.
5. Double-click a name to edit its **local annotation**. Optionally explicitly associate it with a CIO address; this is not proof of physical I/O mapping.
6. Report discrepancies with controller/firmware and sanitized screenshots; **do not publish genuine controller backups**.

## Known limits

- Full text is accessible in pages, but SemanticPreview is currently capped to 200 rungs and 4096 nodes. All available rungs does **not** imply full controller program semantics.
- IONAME.DAT was not provided as a test fixture. The parsing model is based on published examples and **requires verification on a real exported file**, especially character encodings, proprietary sections and indexing.
- `IONAME.DAT` and `CIOPRG.LST` are always unchanged. There is no supported OEM-format comment writer.
- Local annotations currently live in the application's localStorage, not a portable sidecar file. Export/import of sidecars remains an independent milestone.
- The Windows exe is unsigned, portable requires installed WebView2; setup includes offline WebView2 bootstrap. Full corresponding source and SHA256SUMS are attached.
