# MLAD 0.5.0-rc.6 — post-END source and grouped diagnostics

> **Архивное release note — навигационное дополнение от 18.11.2026.** Ниже сохранены сведения о конкретном релизе **rc.6**, опубликованном ранее; они не описывают текущий `main`. Сейчас PR #1–#21 merged и последняя сборка — [rc.9](https://github.com/uzbatsu-beep/MLAD/releases/tag/v0.5.0-rc.9-oem-reference). [Актуальная матрица функций и рисков](../project_status.md). Релизный tag и архив исходников прошлой версии этим дополнением не изменяются.

**Windows x64 read-only engineering preview. Built from PR #18 without requiring merge.**

## Changes

- Actual controller backups may contain `//ALARMN` and `//MESSAGEN` sections **after** the program `END`. The parser now distinguishes these data areas from partially recognized executable code, preserving every original byte and page.
- Any unknown post-END structure is still marked unverified; unsupported/malformed sections are never silently accepted or executed.
- Source status now reports END line number, post-END data length, observed section markers, and unknown trailing lines.
- Diagnostics in the right panel can be grouped by severity/code. Expand a group to navigate every returned source line. Backend diagnostic output limits remain explicit.
- Full source browsing, IONAME overlay annotations, compact file dialogs, and Ladder/advanced zoom remain unchanged.

## Suggested bench checks

1. Open **copies** of CIOPRG.LST for each available controller with the correct family selected.
2. Verify that source rows after END remain visible and textually accurate, but are not counted as executable instructions; check `END L…` and post-END counts.
3. Click the `//ALARM1`, `//MESSAGE1` and other visible markers from the left navigation and verify that the source line matches.
4. Turn diagnostic grouping on/off. Expanded groups must retain every returned line link. Note any warnings that still appear unjustified.
5. Compare SHA-256 to the original before and after; they must match.
6. Compare supported parts of source/diagram against OEM Ladder Editor, especially unknown instructions such as MOV/ADD/SUB/SHL.

## Explicitly NOT supported

Native CIOPRG or IONAME file writing, verified System/User boundaries, firmware equivalence, robot upload, FTP/HSES communication and live I/O. The post-END classification is based on observed source layouts, not a complete vendor grammar.

Windows portable ZIP requires Microsoft WebView2 Runtime. NSIS setup includes an offline WebView2 installer. Source archive and SHA256SUMS are included for licensing/verification. Do not put private CIO programs in public GitHub issues.
