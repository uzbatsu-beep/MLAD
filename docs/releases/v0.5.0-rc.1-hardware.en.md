> **PRE-RELEASE · BENCH / OFFLINE ONLY · NO CONTROLLER WRITES**

This package contains the MLAD engineering UI for preparing Yaskawa Concurrent I/O
ladder bench evaluations on **DX100, DX200 and YRC1000**.

## Contents
- Read-only lossless import/inspection of an existing `CIOPRG.LST`: SHA-256 of source bytes, source spans, parse diagnostics, typed relay/memory validation.
- Semantic expression AST, electrical-style SVG ladder display and cross references.
- Independent `*.graph.json` editor (AND/OR, NO/NC, edit/undo/redo).
- Independent `*.advanced.json` advanced block editor for **TMR**, **CNT** (two independent C/R inputs), **GSTR + GOUT** (one byte, paired).
- Explicit offline timer tick model at 100 ms, rising-edge/reset-priority CNT model, mock 8-bit group copy.
- Read-only native instruction pattern inventory for original programs; unknown patterns remain opaque.
- Sample `*.advanced.json` (synthetic ONLY; never import to controller), bench validation matrix, operator quick-start and result log template.

## Use limitations

**NOT a Yaskawa Ladder Editor replacement, verified CIOPRG compiler, HSES monitor, FTP uploader, motion/servo controller or verified functional-safety device.** A green editor diagnostic is NOT a hardware approval. Native edited `.LST` export and both FTP upload and HSES network monitoring are disabled by backend.

Any actual controller programming or functional I/O exercises must use **OEM-approved Ladder Editor**, a backed-up unmodified `CIOPRG.LST`, formal test authorization, safe non-motion signals and a protected test cell. Never change System Ladder with this application.

## Windows x64 downloads

- **`MLAD-Bench-v0.5.0-rc.1-win-x64-setup.exe`**: offline NSIS installer with embedded WebView2 runtime installer (expected ~127 MiB additional payload). Intended for isolated Windows 10 bench computers. May need administrator permission.
- **`MLAD-Bench-v0.5.0-rc.1-win-x64-portable.zip`**: raw executable + docs and synthetic sample. **Requires Windows WebView2 runtime already installed**; does not install runtimes.
- **`ARTIFACTS_SHA256.txt`**: SHA-256 digests of release files.
- **`package-lock-build.json`**: exact npm dependency resolver snapshot used for this build, because the source tree had no committed npm lockfile.

The Windows executable / installers are **not digitally signed** with a trusted corporate certificate. Windows SmartScreen or enterprise policy can prevent use. Do not bypass local security policy; request IT approval or signed binaries for controlled deployment.

## First-run smoke test (no controller)

1. Verify the SHA-256 of the downloaded installer or portable ZIP against `ARTIFACTS_SHA256.txt`.
2. Start MLAD with **no robot network connected**. Verify the yellow **STAND / OFFLINE** banner and displayed version.
3. Select **TMR · CNT · GSTR/GOUT**, add each type and inspect port labels: TMR start; CNT **C** and **R**; GRP GSTR and GOUT byte addresses.
4. Enter TMR M010 preset 100: 100 manual +100 ms steps should reach Q=1 after 10 s simulated time. Reset start and confirm reload. **This is simulated logical time**, not Windows wall clock.
5. Enter CNT M020 preset 3, toggle C OFF→ON three times, verify no recount while held, then enable R and verify immediate reset.
6. Enter GSTR #20010, GOUT #70030. Mock a known byte (e.g. 0x55) and verify identical output byte.
7. Save and reopen **`*.advanced.json`**. Import a customer-approved source `CIOPRG.LST` only through ** Viewing CIOPRG.LST**, read-only.
8. Verify that **FTP / HSES** operations are disabled. **Do not attempt to upload the advanced JSON as CIOPRG.LST.**

For real-device testing, first complete `docs/advanced_hardware_test_matrix.md` and record results in the provided CSV template. None of those real-device cases have been executed by this release pipeline.
