## Достигнутые цели

Ржавый парсер `src-tauri/src/compiler/lossless.rs` Работает на **raw байтах**. Он не использует декодирование UTF-8 в качестве условия успешного импорта. Он сохраняет каждый байт, включая последовательности символов BOM, не-UTF-8, белое пространство и окончания CRLF/LF/CR. `copy_original()` байт за байтом; отредактированный/экспортированный/рекомпилированный путь не существует.

Парсер вычисляет a **SHA-256 Отпечаток неизменяемого байтового снимка ** для происхождения; он отображается в инспекторе и изменяется, если какой-либо оригинальный байт изменяется.

Парсер поддерживает полную последовательность линий с:

- 1 основанные номера линий;
- байт охватывает всю линию и ее содержимое без EOL;
- оригинальный тип EOL;
- типизированный *overlay* для ограниченного набора инструкций, включая оригинальные операнды и байтовые пролеты;
- раздельная диагностика на неподдерживаемые мнемоники и недействительные операнды;
- резюме проверки с ограниченным предварительным просмотром пользовательского интерфейса и диагностикой.

The `cmd_inspect_cioprg` Команда Таури принимает местное `.LST` Путь и ** явный профиль контроллера**, считывает максимум 16 МБ и возвращает предварительный просмотр и диагностику. **не пишет, не редактирует, не компилирует, HSES or FTP action**. The UI provides a read-only inspector under “Просмотр CIOPRG.LST"Оригинал `cmd_load_project` продолжает отвергать `.LST` Файлы: возвращает старую модель JSON, которая не может представлять все исходные конструкции.

## Лексическое признание

| Input | Interpretation | Notes |
|---|---|---|
| Пустая линия | Empty | Все оригинальные байты сохранены |
| `*` or `;` в начале | Comment | `;` рассматривается как комментарий к наследию; семантика непроверенная |
| `//...` or `/...` | Directive | Точная семантика раздела непроверенная |
| `//$M` + 8 строк | Известный маркер заголовка + наложения строк | Каждая строка должна иметь 10 целых текстовых полей; никогда не нормализовать значения. |
| `STR`, `STR-NOT`, `AND`, `AND-NOT`, `OR`, `OR-NOT`, `OUT` | Типичные инструкции bit-operand | Канонические ожидания `#XXXXX` с проверкой семейного адреса |
| `AND-STR`, `OR-STR` | Распознанный структурный код | zero operands; **сам lexer не строит execution graph; отдельный `semantic.rs` обрабатывает подтверждённое булево подмножество** |
| `TMR`, `CNT` | Тип назначения / наложение источника | destination `Mxxx`Источник `Mxxx` or unsigned decimal; **lexer не доказывает stateful семантику; `advanced.rs` содержит только локальные test-модели** |
| `GSTR`, `GOUT` | Тип байт-группового операнда | консервативная проверка пар и адресов в `advanced_source.rs`; полное vendor-поведение всё ещё требует fixtures |
| Все остальное | Неподдерживаемый / непрозрачный | предупреждать, сохранять байты и пролеты; никогда не удалять |

The `//$M` Заголовок соответствует восьми группам из десяти значений от M550..M559 до M480..M489, с конкретными значениями приложения. Разбиение строки на десять чисел ** не разрешает изменять эту строку.

## Граница безопасности

** Парсер не должен подразумевать редактируемое владение Системой/Пользователем.** Струна `//USER` (или комментарий, содержащий ПОЛЬЗОВАТЕЛЯ) не принимается в качестве доказательства авторизованной области Лестницы пользователя. `InspectionReport.system_user_boundaries_verified` remains `false` для каждого входа.

** Никакого экспорта файлов.** `edited_export_allowed` is `false` для всех отчетов, независимо от диагноза. Это остается таковым даже для синтаксически простого файла, поскольку грамматика на уровне файлов и защищенные области еще не проверены.

** Не истолковывайте чистый отчет парсера как успешную проверку контроллера.** Подмножество распознает некоторые инструкции, но не доказывает правильность владения реле, семантику графа ветвей, порядок разделов файлов или совместимость прошивки контроллера. Старый без потерь `parser.rs` Остается только для исторических тестов JSON и не используется для проверки файлов CIO.

## Tests

Испытания в подразделении `src-tauri/src/compiler/lossless/tests.rs` verify:

1. Точное круглое путешествие для LF, CRLF, CR, конечной линии без терминатора.
2. BOM, произвольное не-UTF-8 и непрозрачное бинарное сохранение.
3. Известные мнемоники, `#00010` ведущие нули, пролеты байтов источника.
4. `//$M` восьмирядный заголовок, недействительные / усеченные заголовки.
5. Зависимая от контроллера классификация адресов и недействительные битовые индексы.
6. Неизвестные инструкции, директивы и комментарии никогда не отбрасываются.
7. Превью усечение и никогда не редактируемый статус.
8. Детерминированное распыление байтов для 256 различных произвольных входов.\n9. SHA-256 Проверка ответов и обнаружение изменений.

### Остающиеся критерии приемлемости

Полный **проверенный** парсер требует авторизованного оригинала `CIOPRG.LST` экспорт из каждого DX100, DX200, YRC1000, с моделью/программным обеспечением/приложением и записанным хэш-файлом. Фактические данные могут быть чувствительными; используйте частные устройства или анонимизированные репрезентативные сегменты с явного разрешения.

Прием перед любым отредактированным экспортом: установите границы раздела «Система/Пользователь» и грамматику заголовка из фактического экспорта, охватите полную схему инструкций и выполнение филиала AST, сравните с Ladder Editor 32 на реальных комплектах креплений, докажите сохранение байтов для нетронутых защищенных разделов и независимо просмотрите процедуру передачи файлов. ** Этого PR недостаточно для безопасного программирования контроллера.

## Связь с новой архитектурой

- Следующий уровень `semantic.rs` строит булевые выражения, распознаёт часть `PART/END` и предупреждает о stateful блоках. Он **не** заменяет `copy_original()`.
- `advanced_source.rs` может показать **узкие** типовые последовательности TMR/CNT/GSTR/GOUT; неизвестная топология не превращается в валидную native цепь.
- `GraphWorkspace` и `AdvancedBlocksPanel` — независимые JSON-редакторы; двойной щелчок из PR #8 **никогда не делает оригинальный LST редактируемым**.
- Golden fixture и OEM round-trip: [controller_fixture_intake.md](controller_fixture_intake.ru.md); системные ограничения: [cioprg_lst_spec.md](cioprg_lst_spec.ru.md).
