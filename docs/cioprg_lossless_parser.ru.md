# Lossless-парсер CIOPRG.LST — контракт реализации PR #2

> **Статус и применимость:** документ описывает подмножество, реализованное и проверенное до/по PR #21, **не** утверждает прекращения разработки на этом этапе. Текущее состояние `main` после [PR #29](https://github.com/uzbatsu-beep/MLAD/pull/29) и раздельные уровни CI/UserSmoke/OEM — [project_status.md](project_status.ru.md). Он не разрешает native writer, HSES или реальный scan.

**Статус после merged PR #21 (18.11.2026):** read-only парсер инспектирования работает; **полного OEM-совместимого перекомпилятора файлов НЕТ**. Семейства: DX100, DX200, YRC1000.

## Реализованные цели

Rust-парсер `src-tauri/src/compiler/lossless.rs` обрабатывает **исходные байты**; успешный импорт не требует UTF-8-декодирования. Он побайтово сохраняет BOM, не-UTF-8 последовательности, пробельные символы и варианты окончаний строк CRLF/LF/CR. `copy_original()` возвращает исходные байты без изменений; пути записи изменённого экспорта или повторной компиляции **не существует**.

Парсер рассчитывает **SHA-256 исходного неизменяемого набора байтов** для прослеживаемости; хеш отображается в Inspector и изменится при изменении любого байта источника.

Для всех строк сохраняются:

- номера строк с единицы;
- байтовые диапазоны всей строки и её содержимого без EOL;
- исходный тип EOL;
- типизированное *наложение* для ограниченного набора команд, включая точную запись операндов и их байтовые spans;
- самостоятельные диагностики неизвестных мнемоник и некорректных операндов;
- сводка инспекции с ограниченным UI-просмотром и диагностикой.

Команда Tauri `cmd_inspect_cioprg` получает путь к локальному `.LST` и **явно выбранный профиль контроллера**, читает **не более 16 MiB**, возвращает предварительный просмотр и предупреждения. В ней **нет** записи, редактирования, компиляции, HSES или FTP. UI предоставляет read-only Inspector «Просмотр CIOPRG.LST». Прежняя `cmd_load_project` продолжает отклонять `.LST`: старый JSON-редактор не может выразить все нативные конструкции.

## Только лексическое распознавание

| Вход | Классификация | Примечание |
|---|---|---|
| Пустая строка | Empty | Все байты сохраняются |
| `*` или `;` в начале | Comment | `;` считается устаревшим признаком комментария, семантика не подтверждена |
| `//...` или `/...` | Directive | Семантика разделов не подтверждена |
| `//$M` + 8 строк | Известный маркер заголовка + наложения строк | В каждой ожидаются 10 целочисленных текстовых полей; значения не нормализовать |
| `STR`, `STR-NOT`, `AND`, `AND-NOT`, `OR`, `OR-NOT`, `OUT` | Типизированная битовая команда | Канонический `#XXXXX`, диапазон зависит от семейства |
| `AND-STR`, `OR-STR` | Известная структурная команда | Без операндов; **лексер не строит граф исполнения**, отдельный `semantic.rs` обрабатывает доказанное булево подмножество |
| `TMR`, `CNT` | Наложение типов источника/назначения | Назначение `Mxxx`, источник `Mxxx` или unsigned decimal; **лексер не доказывает stateful-семантику**, `advanced.rs` содержит только локальные тестовые модели |
| `GSTR`, `GOUT` | Типизированный байтовый групповой операнд | Консервативная проверка пар/адресов в `advanced_source.rs`; полное OEM-поведение требует fixtures |
| Все остальные формы | Unsupported / opaque | Предупреждение, исходные байты и spans сохраняются |

Заголовок `//$M` соответствует восьми десяткам значений от M550..M559 до M480..M489 с приложенчески зависимым смыслом. Разбор строки в 10 чисел **не разрешает** её изменение.

## Ограничения безопасности

**Нельзя считать, что парсер установил границы редактирования System/User.** Строка `//USER` или комментарий со словом USER **не является** доказательством разрешённой области User Ladder. `InspectionReport.system_user_boundaries_verified` всегда равен `false`.

**Изменённый файл не экспортируется.** `edited_export_allowed` равен `false` в любом отчёте, даже без ошибок: полный формат файла и защищённые области не подтверждены.

**Успешный отчёт парсера — не успешная OEM-валидация.** Распознанный набор не доказывает права на реле, правильность ветвлений, порядок разделов и совместимость с firmware. Старый `parser.rs`, не сохраняющий все байты, нужен лишь для исторических JSON-тестов, **не** для просмотра CIO-файлов.

## Тесты

Unit-тесты `src-tauri/src/compiler/lossless/tests.rs` проверяют:

1. Побайтовую неизменность для LF, CRLF, CR и последней строки без окончания.
2. Сохранение BOM, произвольных не-UTF-8 и непрозрачных двоичных данных.
3. Известные мнемоники, ведущие нули `#00010`, байтовые spans.
4. Восемь строк `//$M` и неполные/ошибочные заголовки.
5. Классификацию адресов по семействам и запрещённые индексы битов.
6. Отсутствие скрытого отбрасывания неизвестных инструкций, директив и комментариев.
7. Ограниченный предварительный просмотр и неизменно запрещённое редактирование.
8. Детерминированный fuzz-тест байтов для 256 различных произвольных входов.
9. Проверку известного SHA-256 и обнаружение изменений.

### Оставшиеся критерии приёмки

Для **полной подтверждённой** грамматики нужны разрешённые к анализу оригинальные `CIOPRG.LST` для DX100, DX200 и YRC1000 с точными моделью/firmware/application и хешами. Реальные файлы могут быть конфиденциальны: используйте приватные fixtures либо санкционированные обезличенные фрагменты.

До рассмотрения изменённого экспорта нужно установить System/User границы и заголовки по реальным файлам, покрыть полную схему инструкций и AST исполнения ветвей, сравнить с Ladder Editor 32 на наборе реальных разрешённых образцов, доказать неизменность защищённых разделов и провести независимый review процедуры передачи файла. **PR #2 недостаточен для безопасного программирования робота.**

## Связь с новой архитектурой

- Следующий уровень `semantic.rs` строит булевые выражения, частично распознаёт `PART/END` и предупреждает о stateful-блоках. Он **не заменяет** `copy_original()`.
- `advanced_source.rs` показывает только **узкие** известные последовательности TMR/CNT/GSTR/GOUT; неизвестная топология не объявляется валидной native-цепью.
- `GraphWorkspace` и `AdvancedBlocksPanel` — отдельные JSON-редакторы; double-click PR #8 **никогда** не включает редактирование оригинального LST.
- Golden fixtures/OEM round-trip: [controller_fixture_intake.md](controller_fixture_intake.ru.md); границы нативного формата: [cioprg_lst_spec.md](cioprg_lst_spec.ru.md).
