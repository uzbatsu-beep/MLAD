# MLAD PR #20 — семантическая верификация и аудит ссылок

**Актуально на 18.11.2026:** PR #20 и PR #21 **merged**. Статический аудит и автономные OEM manual-derived векторы реализованы, но **реальные EN/scan/flags не измерялись на контроллере**. Таблица ниже — исторический исходный статус до PR #21; текущий документальный уровень дополнен в [исследовании пяти команд](oem_5_opcode_analysis.md). [Матрица готовности](project_status.md).

## Источники и уровень доказательности

1. Официальный индекс [YRC1000 Concurrent I/O R12](https://knowledge.motoman.com/hc/en-us/articles/40670912825362-YRC1000-OPTIONS-INSTRUCTIONS-FOR-CONCURRENT-I-O-R12) подтверждает наличие в руководстве §12.2.17 ADD, §12.2.18 SUB, §12.2.24 MOV, §12.2.29 SHL, §12.2.30 SHR и §12.3 Arithmetic Flag. **Индекс сам по себе не доказывает поведение команды**.
2. [YRC1000 Ladder Editor manual HW1483388](https://www.motoman.com/getmedia/7DCAB851-59B3-4698-97FB-AE39E45FD106/179482-1CD) подтверждает наличие этих инструкций в меню редактора. Не доказывает особенности сканирования, статуса реле и эквивалентность поколений.
3. [docs/typed_opcode_grammar.md](typed_opcode_grammar.md) фиксирует типизированные **формы**, добавленные PR #19. Это результат синтаксического анализа, не измерения результатов выполнения.
4. Пять настоящих CIOPRG.LST использовались ранее для приватной инвентаризации форм. Доступные синтетические тесты **не** подтверждают OEM-семантику. Настоящие файлы/адреса не публиковать.

## Актуальная классификация после PR #21

| Opcode | Лексическая форма | Формула одиночной операции в руководстве | Флаги в руководстве | Реальный контроллер |
| --- | --- | --- | --- | --- |
| MOV | TypedCandidate | Передача S→D (для 16-bit) | MOV byte Carry — граничная неопределённость 256 | **Не проверен** |
| ADD | TypedCandidate | `(S1+S2) mod 65536` | Carry/Zero по 16-bit результату | **Не проверен** |
| SUB | TypedCandidate | `(S1−S2) mod 65536` | Borrow/Zero | **Не проверен** |
| SHL | TypedCandidate | Логический 16-bit left shift | Carry по вытесненному биту; n=0/16 неопределённо | **Не проверен** |
| SHR | TypedCandidate | Логический 16-bit right shift | Carry по вытесненному биту; n=0/16 неопределённо | **Не проверен** |

**ManualDerived не означает BenchVerified.** Reference-ядро изолировано от CIO/IPC. За условия EN при взаимодействии нескольких инструкций, scan flags и конкретную firmware остаётся ответственной будущая независимая верификация.

## Реализовано в PR #20: ограниченный статический аудит

\`src-tauri/src/compiler/typed_dataflow.rs\`:

- Используются только исходные \`TypedCandidate\` из побайтового анализатора. Никаких вычислений \`MOV\`, \`ADD\`, \`SUB\`, \`SHL\`, \`SHR\`.
- \`CandidateRole\`: **Source**, **ShiftAmount**, **Destination** — гипотезы *позиции операнда* на основании формы, не факт обращения к памяти.
- \`possible_previous_definition\` означает **строгое совпадение текстового имени M-регистра с предыдущим типизированным местом назначения**. Оно никогда не означает гарантированную передачу значения или выполнение команды.
- Совпадения \`#XXXX0\`, \`W#XXXX0\` не создают связи, потому что перекрытие битов/байтов/слов и адресная карта не подтверждены.
- Контекст сбрасывается на \`PART\`, \`END\`, любой иной известной булевой/расширенной инструкции, неизвестной/ошибочной инструкции и неподтверждённой секции. Сканирование после END прекращается.
- Отчёт содержит количество всех кандидатов и всего предположительных совпадений, но подробный список ограничен первыми 1000 записями; \`events_truncated\` явно обозначает сокращение.
- \`semantics_verified=false\`, \`scan_order_verified=false\`, \`arithmetic_flags_verified=false\`, \`native_write_allowed=false\`. Никаких путей для загрузки/редактирования native CIO нет.

## Следующий обязательный протокол OEM-верификации

Проводить **только на отдельном испытательном стенде и с разрешением владельца оборудования**, без автоматической загрузки CIO или изменения системного Ladder:

1. Зафиксировать контроллер (DX100/DX200/YRC1000), версию системного ПО, опции, OEM manual revision, конфигурацию регистров и SHA-256 выгрузки.
2. Сверить допустимые формы через штатный Ladder Editor; все несовпадения оформить как \`unverified\`.
3. Для каждой команды отдельно установить: точную операцию при EN=0/1, предельные значения, переполнение, порядок обновления адреса назначения, Carry/Zero/Error, влияние на последующие инструкции.
4. Выполнять контролируемые тесты только в изолированной среде без подключённых исполнительных механизмов и с собственным регламентом безопасности. PR #20 **не предлагает и не содержит сценария загрузки на робот**.
5. Подтвердить наблюдения снимками OEM IDE/контроллера, повторяемыми тестами и ссылками на нужную редакцию документации; если доказательства недостаточны, состояние остаётся \`Unknown\`.
6. Только после отдельного code review допустимо добавить исполнение **частного проверенного подмножества** в изолированный симулятор. Авторизация native writer / HSES / FTP — независимый запрет и отдельный этап.

## Критерии приёмки PR #20

- Синтетические Rust-тесты: точные M-имена, отсутствующие/неподтверждённые операнды, PART/END, блокировки на unknown/boolean, ограничение вывода, отсутствие alias-выводов, побайтовая неизменность.
- UI показывает лишь предположительные текстовые связи и позволяет перейти к исходной строке; отсутствие подтверждения исполнения видно без открытия документации.
- CI Rust/TypeScript и Windows MSVC успешно; PR не сливать до разрешения владельца.

## PR #21 — документальная семантика, без стендовой эквивалентности

Таблица неизвестных выше отражает состояние **до** изучения YRC1000 R12 §12.2–12.3 и DX100 Rev.0. Условия EN=ON, отдельные формулы и таблицы флагов теперь документально описаны для всех пяти команд в [исследовании](oem_5_opcode_analysis.md). Это **не** переводит реальный CIOPRG в исполняемое подмножество и не меняет `semantics_verified=false`, `scan_order_verified=false`.
