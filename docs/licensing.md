# Правовая политика MLAD — GNU GPL-3.0-only

**Дата решения:** 17.11.2026. **Статус:** GPLv3 зафиксирована как выбранная лицензия для исходного кода, но полный аудит прав и выполнения условий распространения **ещё не завершён**.

## 1. Какая именно лицензия

- **Идентификатор SPDX:** `GPL-3.0-only`.
- **Точный текст:** [../LICENSE](../LICENSE) — GNU General Public License, Version 3, 29 June 2007.
- **Важное различие:** `GPL-3.0-only` разрешает использовать именно версию 3. **Опция «or any later version» не предоставляется**. Для будущего перехода на `GPL-3.0-or-later` понадобится отдельное решение авторов/правообладателей, имеющих такие полномочия.
- **Источники полного текста и правил использования:** [GNU GPLv3](https://www.gnu.org/licenses/gpl-3.0.html), [GNU: How to use GNU licenses](https://www.gnu.org/licenses/gpl-howto.html), [SPDX: GPL-3.0-only](https://spdx.org/licenses/GPL-3.0-only.html).
- **Метаданные:** `package.json` / `src-tauri/Cargo.toml` должны содержать `GPL-3.0-only`.

В частности, при распространении исполняемого MLAD или модифицированных бинарных сборок возникают обязательства по предоставлению соответствующего исходного кода и сохранению необходимых уведомлений согласно GPLv3. Нельзя считать размещение исходников на GitHub автоматическим исполнением **всех** условий каждого способа поставки.

## 2. Что относится и не относится к GPL MLAD

| Объект | Правовой режим |
|---|---|
| Собственный исходный код MLAD, на который авторы имеют права | GPL-3.0-only |
| Собственные изменения, принятые в репозиторий | Должны быть совместимы с GPL-3.0-only |
| Rust/npm библиотеки, WebView2 и системные компоненты | **Сохраняют собственные** лицензии и уведомления |
| Руководства, стандартные чертежи и схемы производителя | Не становятся GPL только из-за цитирования в MLAD |
| Оригинальные/обезличенные `CIOPRG.LST` клиента или робота | Права владельца файла; не открываются автоматически |
| Торговые марки Yaskawa / Motoman, логотипы и товарные обозначения | Не лицензируются GPL MLAD |
| Пользовательские JSON-проекты/сохранённые данные | Не лицензируются автоматически GPL только потому, что созданы в MLAD |

**MLAD не является официальным продуктом Yaskawa, не одобрен производителем и не сертифицирован для управления роботами.** Запреты native writer, HSES и FTP сохраняются независимо от правового статуса.

## 3. Авторство и подтверждение прав — открытый пункт до принятия PR

Решение пользователя о GPLv3 не устанавливает личности правообладателей. Из прежнего `Cargo.toml` известно только поле `authors = ["Antigravity Developer"]`, которое является техническим заполнителем, **не подтверждённой юридической атрибуцией**.

**Перед слиянием/новым выпуском нужно:**

1. Назвать фактического правообладателя (физическое лицо / организация / несколько авторов) и год начала создания оригинальных частей MLAD.
2. Проверить, нет ли прав работодателя, контрагентов и иных соавторов на части исходного кода и файлов. Получить согласие тех, чьи права необходимы для GPL-распространения.
3. Уточнить происхождение ранее включённых изображений/иконок, шаблонов, заимствований и сгенерированных файлов; удостовериться в праве их распространения.
4. Зафиксировать подтверждённые copyright notices в `README.md`/отдельном документе и по возможности в исходных файлах. **Не подставлять выдуманное имя или имя GitHub-аккаунта**.
5. Отдельно пересмотреть `Cargo.toml` `authors` и Tauri app identifier после согласования авторства и политики обновления Windows.
6. Проверить правообладание/лицензии всех встроенных шрифтов, примеров, ресурсов и исходных материалов тестовых роботов.

Пока эта проверка не завершена, нельзя безусловно утверждать, что каждая строка публичного репозитория принадлежит одному заявленному лицу.

## 4. Сторонние зависимости и Windows-сборки

- **Не менять лицензии сторонних модулей** в их исходных каталогах. Соблюдать их условия и необходимые copyright/NOTICE файлы.
- Для новых релизов сформировать машинно-проверяемый SBOM/реестр пакетов npm и Rust с версиями, SPDX license ID, источником и указанием о распространении бинарников.
- `package-lock.json` и переход на `npm ci` — отдельный PR по воспроизводимости; он необходим для достоверного перечня распространяемых зависимостей.
- Для Windows NSIS/portable ZIP добавить текст `LICENSE`, подходящие сторонние уведомления и ясную ссылку на **исходники именно выпущенного commit/tag**. Учитывать соответствующие обязательства GPLv3 при передаче бинарных файлов.
- Ранее выпущенный `v0.5.0-rc.1-hardware` создан **до** этого изменения; нельзя считать, что его ZIP автоматически пополнился лицензией или уведомлениями. Не переписывать tag/релиз задним числом.
- Проверить лицензии Tauri, WebView2 Runtime и других обязательных средств дистрибуции отдельно; не полагаться на предположение о совместимости без перечня зависимостей.

## 5. Процесс поддержки

- PR на новый код указывает происхождение существенных внешних материалов и лицензии включаемых компонентов.
- В шаблоне PR предусмотреть проверку «нет клиентских `CIOPRG.LST` / секретов / авторских руководств».
- При поступлении запроса об уязвимости использовать будущую `SECURITY.md`; лицензирование и safety — разные вопросы.
- При изменении лицензии или принципов внешней поставки нужен отдельный юридический/организационный review.

**Следующий шаг после утверждения правообладателя:** добавить точный copyright notice, проверить third-party notices и подготовить compliant Windows release workflow. Этот документ описывает инженерно-правовые задачи и не является индивидуальным юридическим заключением.
