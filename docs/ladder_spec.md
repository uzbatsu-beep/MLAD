# Спецификация синтаксиса и инструкций языка листингов Yaskawa Motoman

Программа Concurrent I/O для роботов Motoman на низком уровне представляет собой текстовый файл листинга (Instruction List) с расширением `.LST`. Графический редактор на Tauri должен компилировать граф в этот формат и уметь выполнять обратный парсинг текстового файла в структуру нод.

## 1. Структура файла .LST

Файл программы состоит из заголовка, тела с инструкциями логики и маркера завершения.

```text
/JOB
//NAME CONCURRENT
//POS
///NPOS 0,0,0,0,0,0
//INST
IOCPT STRSTART        ; Маркер начала секции исполнения логики ПЛК
STR 70010              ; Первая цепь (Rung 1)
AND 10012
OUT 50010
STR 10015              ; Вторая цепь (Rung 2)
TMR 1, 10
OUT 70020
END                    ; Маркер конца программы
```

---

## 2. Базовые логические инструкции (Bit Instructions)

Эти инструкции формируют основные последовательные цепи и ветвления на холсте (компоненты контактов и катушек).

| Мнемоника | Аргумент | Описание | Графическое представление |
| :--- | :--- | :--- | :--- |
| **`STR`** | Адрес бит | Start. Начало новой цепи или параллельной ветки. | Нормально-открытый контакт (в начале) |
| **`STR-NOT`**| Адрес бит | Start Not. Начало цепи с инверсией. | Нормально-закрытый контакт (в начале) |
| **`AND`** | Адрес бит | Логическое И. Последовательное подключение. | Нормально-открытый контакт в линии |
| **`AND-NOT`**| Адрес бит | Логическое И-НЕ. Последовательная инверсия. | Нормально-закрытый контакт в линии |
| **`OR`**  | Адрес бит | Логическое ИЛИ. Параллельное подключение. | Параллельный нормально-открытый контакт |
| **`OR-NOT`** | Адрес бит | Логическое ИЛИ-НЕ. Параллельная инверсия. | Параллельный нормально-закрытый контакт |
| **`OUT`** | Адрес бит | Output. Выходная катушка цепи. | Элемент катушки `( )` на правом краю |

### Правила группировки ветвлений:
Для создания сложных параллельных блоков с несколькими элементами используются операторы группировки:
*   **`AND-STR`**: Объединяет параллельные блоки последовательно.
*   **`OR-STR`**: Объединяет последовательные блоки параллельно.

## 3. Функциональные блоки (Таймеры, Счетчики, Системные функции)

Функциональные блоки на холсте отображаются в виде прямоугольников (Boxes) с входными и выходными пинами управления.

### Таймер (`TMR`)
Выполняет задержку включения сигнала.
*   **Синтаксис:** `TMR [Номер_Таймера], [Уставка]`
*   **Параметры:** 
    *   *Номер:* константа от `1` до `256` (в зависимости от контроллера).
    *   *Уставка:* Дискретность 0.1 секунды. Константа или M-регистр.
*   **Пример:** `TMR 5, 25` — задержка 2.5 секунды для таймера №5.

### Счетчик (`CNT`)
Подсчитывает количество импульсов на входе.
*   **Синтаксис:** `CNT [Номер_Счетчика], [Уставка]`
*   **Параметры:**
    *   *Номер:* уникальный индекс счетчика.
    *   *Уставка:* количество импульсов (константа или значение из M-регистра).

### Специальные инструкции передачи данных
*   **`MOV`**: Копирование значения из одного M-регистра в другой или запись константы в регистр.
    *   *Пример:* `MOV M001, 100` (записать 100 в регистр M001).

## 4. Правила генерации AST (Abstract Syntax Tree) на Rust

Для парсинга и компиляции бэкенд строит дерево промежуточного представления. Каждая цепь (`Rung`) описывается отдельной структурой.

```rust
// Примерная концепция структуры данных в компиляторе Rust
pub struct Rung {
    pub id: usize,
    pub comment: Option<String>,
    pub operations: Vec<Instruction>,
}

pub enum Instruction {
    Str(u32),       // Адрес операнда
    StrNot(u32),
    And(u32),
    AndNot(u32),
    Or(u32),
    OrNot(u32),
    Out(u32),
    Tmr(u32, u32),  // Номер таймера, уставка
    // Другие функциональные блоки
}
```

При парсинге `.LST` файла с помощью крейта `nom` пустые строки и комментарии, начинающиеся с точки с запятой `;`, должны игнорироваться, но сохраняться в метаданных ноды для отображения подсказок на фронтенде.
