### Exact source-backed contracts

#### TMR — 12.2.12

```text
STR #70010
TMR M010,100
OUT #70100
```

- Current value `M000..M559`.
- Preset: decimal `0..65535` or register `M000..M999`, interpreted as unsigned 16-bit value.
- Clock unit **100 ms** per count: `100 → 10.0 s`. The vendor instruction is ON-delay.
- With start **OFF**, the current value is reloaded from preset and TMR contact is OFF.
- With start **ON**, current value decreases each 100 ms until 0; TMR contact then ON. Held ON until start goes OFF.
- Device power-on resets timer; extra details around changing register presets, value 0 and scan timing require bench confirmation.

The offline helper `TimerState::tick(start,preset)` takes **one explicit 100 ms tick**. It does not run wall-clock time or open any hardware connection. Missing input values in the expression evaluator produce UNKNOWN.

#### CNT — 12.2.13

```text
STR #70010   ; C (count)
STR #70011   ; R (reset)
CNT M020,3
OUT #70110
```

- **Two independent Boolean inputs**, C for count and R for reset; don't collapse them into a single enable.
- Current value `M000..M559`. Preset: decimal `0..65535` or M000..M999.
- **Rising OFF→ON edge of C** decrements the current value by 1 while R is OFF.
- R=ON reloads preset and turns counter contact OFF, and has priority over simultaneous C.
- Current=0 makes CNT contact ON; stays ON until reset, subsequent count edges must not wrap below zero.
- Device power-on resets counter. If reset is released while C stays high, no extra artificial rising edge is generated by our model.
- The test helper `CounterState::scan(count,reset,preset)` simulates exactly **one input sample/scan** with explicit states. It does not model real controller scan time.

#### GSTR / GOUT — 12.2.14

```text
GSTR #20010
GOUT #00010
```

- **Paired instructions**, never assume that GSTR alone writes anything or that GOUT is legal without a matching GSTR.
- Each operand is a **byte group of eight relays**, starting at bit 0: format `#XXXX0`.
- First instruction supplies one source byte; second directs the same eight bits to destination byte.
- The operation is **not** eight independent freely schedulable BOOL outputs. Byte-group destination overlap with any individual OUT is diagnosed.
- `group_copy(byte)` is an identity in a *mock offline memory model*. It is NOT an HSES/PLC write.
- Same source/destination address legality depends on selected controller and relay class. An address being in range is not equivalent to hardware writable.

### Additional manufacturer diagnostics

Errors 4040 (duplicate OUT/GOUT/register writer), 4100 (reused current register), 4150 (unpaired GSTR/GOUT), 4220 (more than 100 TMR/CNT/arithmetic instructions) and 4230 (TMR/CNT syntax) are represented in conservative validation. **The 100-instruction budget includes arithmetic and potentially existing protected program sections that MLAD cannot inventory.** The editor warns near the budget; it does not claim remaining capacity.

## Architecture and file-safety separation

1. `src-tauri/src/compiler/advanced.rs` — typed JSON block DTOs and checkers; deterministic offline `TimerState`, `CounterState`, `group_copy`, and three-valued Boolean condition evaluator.
2. `src-tauri/src/compiler/advanced_source.rs` — **read-only** recognition of simple, manually confirmed instruction sequences in the immutable `LosslessDocument`. A complex expression is flagged as unverified rather than being transformed to a synthetic circuit.
3. `src-tauri/src/compiler/lossless.rs` — fixed TMR/CNT operand lexer: current M000..M559, 16-bit decimal preset, and M000..M999 preset register. All original bytes, line endings and SHA-256 still preserved exactly.
4. `src/components/AdvancedBlocksPanel.tsx` — independent dedicated editor with distinct C/R inputs, preset type, register and output fields, profile selection and explicit offline single-step buttons. A `GROUP` card always contains **both** GSTR and GOUT. Since PR #7 **all blocks** appear in the same scrollable workspace, with an independent last *manual* sample per block; edits reset outdated result to UNKNOWN.
5. `src/components/AdvancedBlockDiagram.tsx` — SVG function block with visible TMR/CNT state, C/R inputs and group ports plus group bit LEDs; never draws a misleading bare contact-to-coil wire. Since PR #8 simple C/R, current Mxxx, preset, OUT and byte operands can be edited by double-click in **JSON**; complex conditions remain in the expression editor.
6. `src/components/CioprgInspector.tsx` — source inventory, validated simple example diagrams and explicit unknown-pattern warnings. It **cannot** edit a native program.
7. Backend IPC: `cmd_validate_advanced_draft`, `cmd_load_advanced_draft`, `cmd_save_advanced_draft`, `cmd_test_tmr_step`, `cmd_test_cnt_step`, `cmd_test_group_copy`.

**New format:** `*.advanced.json`, schema `version:1`. This is *separate* from `*.graph.json` and legacy `project.json`. It cannot overwrite a `.LST` through an ordinary extension. Existing symlink targets are rejected, previous JSON backed up before write. System file access control remains the responsibility of OS and administrator.

**Import/edit/export boundary:** Native `CIOPRG.LST` files remain immutable read-only snapshots. The new advanced editor has no native serializer. `native_export_allowed=false`, `hardware_test_authorized=false`. The old FTP and unverified HSES monitoring are still denied in the backend.

## Acceptance tests and limitations

Automated Rust tests verify:
- All three controller profiles including differing group byte ranges.
- M559/M560 current register boundary and M999/M1000 preset boundary, unsigned 16-bit preset limits.
- Timer 100 ms countdown, OFF reset and 100 ticks for 10 s.
- Counter OFF→ON counts, held input does not recount, R priority, 0 latching.
- GSTR/GOUT one-byte copying and #XXXX0 alignment.
- Reused current register, duplicate coils, group-bit overlap, restricted destination classes and 4220 count budget.
- Native simple pattern recognition on all three generations, malformed patterns, unpaired/duplicated GOUT and immutable byte round-trips.
- JSON schema and explicit disabled export/test authorization.

Frontend tests verify typed advanced models, group pairing and canonical review-only strings. `MLAD validation` also runs graph/tri-state/inline-operand tests, Rust and TypeScript/Vite; the CI does not independently test real Yaskawa execution.
