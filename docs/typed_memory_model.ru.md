## 1. Адресная модель

Индивидуальное реле битов CIO имеет ровно пять десятичных цифр (каноническая нотация файла). `#XXXXX`), причем последняя десятичная цифра ограничивается `0..7`Наименее значимой цифрой является битовый индекс в восьмибитном канале. Биты `8` and `9` Никогда не существует. Например, `#70017` - восьмой бит канала 7001; `#70018` Это недействительно.

Префикс, такой как `#0...` Все пять цифр должны быть сохранены **. Целое представление является только внутренним ключом и никогда не используется для переформатирования защищенных исходных файлов.

## 2. Точные диапазоны реле семейства контроллеров

Обе конечные точки являются инклюзивными. Окончательная цифра всех пределов диапазона составляет 0-7.

| CIO класс | DX100 | DX200 | YRC1000 |
|---|---:|---:|---:|
| Общий ввод (CIO → работа) | 00010–02567 | 00010–05127 | 00010–05127 |
| Общая производительность (работа → CIO) | 10010–12567 | 10010–15127 | 10010–15127 |
| Внешний вход | 20010–22567 | 20010–25127 | 20010–25127 |
| Внешний результат | 30010–32567 | 30010–35127 | 30010–35127 |
| Конкретный вход (командование роботом) | 40010–41607 | 40010–41607 | 40010–42567 |
| Специфический результат (статус робота) | 50010–52007 | 50010–53007 | 50010–55127 |
| Ввод панели интерфейса | 60010–60647 | 60010–60647 | 60010–60647 |
| Вспомогательное реле | 70010–79997 | 70010–79997 | 70010–79997 |
| Контрольный статус | 80010–80647 | 80010–82007 | 80010–85127 |
| Ввод псевдонима | 82010–82207 | 82010–82207 | 87010–87207 |
| Ввод сети | 25010–27567 | 27010–29567 | 27010–29567 |
| Выход сети | 35010–37567 | 37010–39567 | 37010–39567 |

**Не взаимозаменяемые случаи:**
- `#82010`: DX100/DX200 `PseudoInput`, YRC1000 `ControlStatus`.
- `#87010`Недействительный под DX100/DX200 профиль; `PseudoInput` under YRC1000.
- `#25010`: `NetworkInput` in DX100 but `ExternalInput` in DX200/YRC1000.
- `#37010`: `NetworkOutput` во всех трех; это не обычный `ExternalOutput`.

Диапазон членства ** не** свидетельствует об установленных модулях ввода/вывода или разрешенной команде системы. Несколько сетевых карт / устройств должны быть проверены на фактическую конфигурацию робота.

## 3. M-регистрации: 16-битные значения, класс ≠ разрешение на запись

Задокументированное место регистрации ИТ-директоров для этих трех семей `M000–M999` (1000 регистров). ** Не думайте, что M1000-M3999 существует в CIO** на основе несвязанных с роботом переменных объектов или других продуктов контроллера.

| Класс регистра | Range | Семантика / ограничения |
|---|---|---|
| General | M000–M559 | 16-битный регистр CIO общего назначения; записи зависят от инструкций и владения |
| Аналоговый выход | M560–M599 | Реестр резервного копирования аналоговых выходов; изменения требуют пересмотра конфигурации |
| Аналоговый вход | M600–M639 | Измерение аналогового входа; запретить обычное назначение |
| System | M640–M999 | Значения контроллера/системы; не предоставляйте общий доступ к записи |

Yaskawa дает индивидуальные инструкции с различными ограничениями источника/назначения; например, таймеры и пункты назначения с текущим значением могут быть ограничены общими регистрами, даже если их заданные значения могут ссылаться на более широкий диапазон источников.

Заголовок `//$M` **M480-M559** в восьми нисходящих группах. Реестр, который, как правило, можно записать, все еще может быть зарезервирован; `//$M` Должна быть сохранена собственность системы/пользователя.

## 4. Типы ржавчины и обязанности проверки

```text
ControllerFamily = DX100 | DX200 | YRC1000
RelayBitAddress  = number + channel + bit + RelayClass
RelayGroupAddress = first_bit + (Byte8 | Word16)
RegisterAddress = number + RegisterClass
LadderWritePolicy = Denied | Candidate | RequiresReview
```

- `parse_relay(controller, "#70010")` проверяет пять десятичных цифр ASCII, бит 0-7 и точную таблицу контроллера.
- `parse_register("M256")` checks `M` и ровно три цифры ASCII, затем классифицирует его.
- `parse_group(controller, "#70010", Byte8)` / `parse_group(controller, "W#70010", Word16)` Различают групповые ширины. Он проверяет запуск с нулевым битом, но ** еще не подтверждает ** выравнивание слов по инструкции, пересечения банков или приемлемые классы операндов для конкретных инструкций.
- `relay_write_policy` сознательно консервативны: некоторые классы отрицаются как `OUT` Цели и конкретные контрольные входы требуют пересмотра. ** Кандидат не имеет права писать на аппаратное обеспечение**, только то, что общая категория может быть назначением некоторых инструкций лестницы.
- Владение системной лестницей не выводится из адреса. Пользовательская программа может ссылаться на системные сигналы, не владея их определениями. **System vs. User** - это свойство региона файла/программы, а не свойство адреса ретрансляции.

Наследный валидатор `validate_rungs` assumes YRC1000 только для обратной совместимости; абоненты, работающие с DX100/DX200 ** Должен ** использовать `validate_rungs_for_controller(rungs, family)`. **В новых вкладках UI выбор DX100/DX200/YRC1000 уже реализован** (Graph Workspace, Advanced CIO и Inspector). Старый JSON-интерфейс сохраняет ограничения legacy. Выбор семейства **не** задаёт автоматически точные firmware, установленные опции, физическую конфигурацию и право на запись в робот; export/deployment по-прежнему запрещены.

## Текущее применение профилей после PR #8

- `graph_draft.rs` проверяет JSON-адреса и классы выходов по выбранному семейству.
- `advanced.rs` дополнительно ограничивает current M000–M559 для TMR/CNT, preset M000–M999 или 0–65535, а адреса `GSTR/GOUT` — байтовыми группами с битом 0.
- `inlineOperand.ts` делает **только** предварительную проверку синтаксиса во фронтенде; контроллерозависимые диапазоны проверяет Rust. Успешный inline ввод — не аппаратное подтверждение.
- `lossless.rs` и `semantic.rs` работают по явно указанному профилю при чтении исходного `CIOPRG.LST`, сохраняя неопознанные части без правки.
- Точный model/firmware/application профиль и ограничения физического I/O ещё предстоит подтвердить реальными выгрузками и документацией.

## 5. Контрольный перечень валидации

1. Выберите семейство контроллеров перед исследованием диапазонов.
2. Проверьте синтаксис и битовый индекс; `#70018` / `#70019` Они недействительны, даже если находятся в широком численном диапазоне.
3. Проверьте точные границы диапазона, специфичные для контроллера; пробелы не являются действительными реле.
4. Классифицировать бит/байт/слово/регистрацию отдельно; `W#70010` Не следует читать как небольшую или М-регистрацию.
5. Применяйте схему операнда, специфичную для инструкций, источник/назначение и государственное поведение.
6. Применять ограничения на владение проектами и конфигурацию роботов.
7. Диагностика дублирующих катушек, небезопасных мест назначения и неразрешенных инструкций.
8. Для любого модифицированного файла CIOPRG блокируйте экспорт / развертывание до тех пор, пока не будет проведена независимая проверка.

Единичные тесты для этого базового уровня находятся непосредственно в `memory.rs`Они охватывают границы, различия в генерации, искаженные адреса, псевдовходные данные и сетевой I/O.

## 6. Неразрешенные до тех пор, пока не будут установлены приборы с поддержкой контроллера

- Специфические разрешения на запись для конкретных `SpecificInput` Справка: нет полного разрешения.
- Регистр зарезервированного использования по технологии (сварка/обработка/и т.д.).
- `W#` выравнивание и композитное пересечение диапазона операнда.
- Адреса, зависящие от прошивки / опции, и отсутствующее оборудование ввода / вывода.
- Расширенные или нестандартные адресные пространства ИТ-директоров, если они отдельно документированы для конкретных изменений.
- Полные инструкции/семантика и портовые разрешения HSES (отдельный сетевой поток).
