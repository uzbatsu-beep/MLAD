# MLAD — классификация и диагностика данных после END (только чтение)

**Область действия на 18.11.2026:** PR #18 **объединён**, [Windows rc.6 опубликован](https://github.com/uzbatsu-beep/MLAD/releases/tag/v0.5.0-rc.6-postend); функциональность присутствует в `main`. Описана структура, **наблюдавшаяся** после END, а **не** полная OEM-грамматика и не нативный редактор. См. [текущее состояние](project_status.ru.md).

## Наблюдаемые выгрузки, а не предполагаемая OEM-спецификация

В приватных резервных копиях контроллеров за синтаксически корректной отдельной строкой `END` следуют человекочитаемые сообщения об авариях и событиях. Среди замеченных маркеров разделов: `//ALARM1`, `//ALARM2`, `//MESSAGE1`, `//MESSAGE2`.

Наличие этих фрагментов **не доказывает** универсального формата, совместимости с другими прошивками, права записи или исполняемой семантики. Настоящие исходники роботов **не публикуются** в репозитории как тестовые fixtures.

## Правила разбора

1. Сначала выполняется **побайтовое** сканирование всего источника со смещениями и точным сохранением окончаний строк CRLF/LF/CR.
2. До синтаксически корректного `END` сохраняется поведение существующего частичного парсера инструкций, включая выявление неподдерживаемых мнемоник.
3. После `END` строки **не трактуются как исполняемый Ladder**:
   - **PostEndSection:** регистрозависимые `//ALARM` либо `//MESSAGE` с последующими **1–8 ASCII-десятичными цифрами**; первоначальная запись маркера сохраняется.
   - **PostEndData:** интерпретация байтов внутри наблюдаемого раздела **не выполняется**; сюда же относятся пустые строки.
   - **PostEndOpaque:** текст вне распознанного раздела, неизвестные директивы или байты с NUL. Точные байты сохраняются; выдаётся **одно представительное предупреждение** `PostEndUnknownStructure`, а не предупреждение по каждой записи.
4. Все строки остаются доступны для постраничного просмотра и поиска, сохраняя **полную побайтовую идентичность**. Категории — **только визуальные наложения**.
5. Семантический анализатор пропускает известные строки разделов и данных после END. Неизвестная область после END вызывает ограниченное предупреждение `AfterEnd` и оставляет `subset_analysis_complete=false`; дополнительные цепи Ladder **не выдумываются**.
6. Ошибочная строка `END operand` **не** открывает область данных. Отсутствующий или неоднозначный END автоматически **не исправляется**.

## Интерфейс и критерии приёмки

Строка статуса сообщает номер **первой корректной** строки END, число следующих строк, количество распознанных маркеров и неподтверждённых строк. Исходный текст отображается с отдельными категориями; диагностики группируются по серьёзности и коду. При раскрытии группы доступны **все возвращённые backend** отдельные ссылки на строки. Backend продолжает **ограничивать общее число** возвращаемых диагностик, и UI обязан явно предупреждать об ограничении.

- Синтетические Rust fixtures проверяют смешанные окончания строк, встроенные не-UTF8 байты, неизвестные/неправильные маркеры, ошибочный END и строки данных, похожие на команды Ladder.
- TypeScript-тесты проверяют, что группировка не теряет ссылки на строки, включая сценарий с **525 повторяющимися предупреждениями**.
- **Инвариант безопасности:** изменение native CIOPRG/IONAME, FTP/HSES, загрузка в контроллер и заявления об OEM-эквивалентности остаются запрещены.

## Известные ограничения

Изменение устраняет **определённый класс ложных срабатываний**, но не обеспечивает поддержку других нераспознанных команд (`MOV`, `ADD`, `SUB`, `SHL` и др.), не доказывает адресную карту конкретной прошивки, не предоставляет права изменения System/User и не гарантирует полноты диагностики. Для каждого семейства требуется приватное сравнение с реальной выгрузкой и OEM Ladder Editor.
