# Спецификация сетевого взаимодействия для живого мониторинга сигналов робота Yaskawa Motoman

Для отображения реального состояния контактов и катушек на графическом холсте (онлайн-подсветка активных цепей) бэкенд-модуль приложения на Rust обменивается данными с контроллером по протоколу **High-Speed Ethernet (HSE)**.

## 1. Общие параметры подключения

*   **Протокол транспортного уровня:** UDP (основной для циклического мониторинга) / TCP (для некоторых управляющих пакетов).
*   **Порт по умолчанию:** `8040` (может изменяться в настройках системы робота параметров сети).
*   **Режим работы контроллера:** Робот должен находиться в удаленном режиме управления (`Remote mode`).

---

## 2. Структура пакета HSE (Заголовок и Данные)

Каждый запрос к роботу содержит фиксированный 32-байтовый заголовок идентификации пакета, за которым следует тело команды.

### Формат заголовка пакета (HSE Header):

| Смещение (байт) | Размер (байт) | Тип данных | Название поля | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `0x00` | 4 | Строка (ASCII) | `YERC` | Магическая константа (Идентификатор заголовка) |
| `0x04` | 2 | `u16` | `Header Len` | Длина заголовка (обычно `0x0020` = 32 байта) |
| `0x06` | 2 | `u16` | `Data Len` | Длина последующих данных (тела команды) |
| `0x08` | 1 | `u8` | `Type` | Тип запроса (`1` — запрос данных, `2` — запись) |
| `0x09` | 1 | `u8` | `ID` | Идентификатор пакета (инкрементируется Rust-клиентом) |
| `0x0A` | 2 | `u16` | `Reserved` | Зарезервировано (заполняется нулями `0x0000`) |
| `0x0C` | 20 | Массив `u8` | `Padding` | Дополнительные системные байты выравнивания |

---

## 3. Спецификация команд чтения данных (Подсветка Ladder)

Чтобы обновить состояние контактов на фронтенде Tauri, бэкенд на Rust циклически отправляет пакеты чтения диапазона битовых операндов.

### Пакет-запрос на чтение состояния реле (Read Relay Command):
В теле пакета после заголовка передаются параметры запрашиваемой памяти:

*   **Код команды (Command Code):** `0x03` (Чтение данных памяти).
*   **Тип данных (Instance/Class):** Обозначает целевой диапазон реле:
    *   `0x01` — Вспомогательные реле (`7xxxx`)
    *   `0x02` — Физические входы (`1xxxx`)
    *   `0x03` — Физические выходы (`2xxxx`)
*   **Начальный адрес (Start Address):** Смещение байта относительно начала диапазона.
*   **Количество (Count):** Количество байт для чтения (1 байт содержит состояние 8 последовательных бит схемы).

### Ответ от контроллера:
Контроллер возвращает заголовок `YERC` со статусом выполнения и массив байт. 
*Пример:* Если мы запросили 2 байта с начального адреса пользовательских реле `70010`, и получили байт `0x05` (`00000101` в двоичном виде), это означает:
*   Реле `70010` = **TRUE** (бит 0)
*   Реле `70011` = **FALSE** (бит 1)
*   Реле `70012` = **TRUE** (бит 2)

## 4. Архитектура сетевого модуля на Rust (Tokio Backend)

Для обеспечения высокой отзывчивости интерфейса (не менее 20 Гц обновлений сети) модуль `network` на бэкенде использует асинхронный цикл `tokio::time::interval`.

```rust
// Концептуальная логика циклического опроса
pub async fn start_monitoring_loop(
    target_ip: String, 
    addresses: Vec<u32>, 
    window: tauri::Window
) -> anyhow::Result<()> {
    let socket = tokio::net::UdpSocket::bind("0.0.0.0:0").await?;
    socket.connect(format!("{}:8040", target_ip)).await?;
    
    let mut interval = tokio::time::interval(tokio::time::Duration::from_millis(50));
    
    loop {
        interval.tick().await;
        
        // 1. Формирование бинарного пакета заголовка YERC + Тело команды
        let request_packet = build_hse_read_packet(&addresses);
        socket.send(&request_packet).await?;
        
        // 2. Получение ответа от робота
        let mut buffer = [0u8; 1024];
        let amt = socket.recv(&mut buffer).await?;
        
        // 3. Парсинг байт состояний реле
        let relay_states = parse_hse_response(&buffer[..amt])?;
        
        // 4. Эмиссия реактивного события во фронтенд Tauri
        window.emit("ladder-runtime-sync", relay_states)?;
    }
}
```

### Обработка таймаутов:
Если контроллер робота не отвечает в течение 500 мс, бэкенд обязан отправить во фронтенд Tauri событие `"robot-disconnected"`, чтобы интерфейс визуально перекрасил линии схемы из зеленых/активных в нейтральный серый цвет во избежание дезинформации инженера-наладчика.
