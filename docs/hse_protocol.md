# Yaskawa High-Speed Ethernet (HSES) — статус и требования к верификации

**Проверено в `main` на 18.11.2026:** HSES/FTP runtime удалён из компилируемого backend в PR #13. Мониторинг и загрузка в контроллер отключены; протокол не верифицирован. [Текущий статус](project_status.md).

> **Не использовать этот файл как инструкцию по формированию пакетов для реального контроллера.** Старое содержимое документа включало упрощённую схему YERC и произвольное сопоставление кодов команд/классов I/O. Оно не было подтверждено требуемым руководством и испытаниями. Эти данные **не должны** считаться достоверной реализацией HSES для DX100, DX200 или YRC1000.

## 1. Фактическое состояние исходного кода

- В PR #13 прежний неподтверждённый файл `src-tauri/src/network/mod.rs` **удалён** из исходников, а `pub mod network` отсутствует в `src-tauri/src/main.rs`. Неподтверждённый UDP/FTP клиент не компилируется в MLAD.
- `cmd_toggle_monitoring` возвращает отказ во включении; `cmd_deploy_to_robot` всегда возвращает отказ. Существование Tauri IPC ради совместимости не является поддержкой протокола.
- `TRUE/FALSE/UNKNOWN` и локальные TMR/CNT/GSTR состояния происходят только из ручных/автономных моделей, **не live HSES**.
- Впоследствии PR #25–#29 добавили production CSP, guarded reads, File ID, hardlink/staged safeguards и Windows regression. По-прежнему открыты last check→rename TOCTOU, ACL, backup+target и ручной WebView2 acceptance. Исключение сетевого клиента **не** означает полного security-аудита; [актуальная модель](filesystem_security_pr29.md).

## 2. Что нужно подтвердить по руководствам Yaskawa

Для каждого поколения и версии firmware отдельно установить:

1. **Транспортные требования:** UDP/TCP, порт и условия доступности опции, режимы/права чтения, ограничения подключения; не предполагать одинаковое поведение для всех систем.
2. **Полный заголовок YERC:** размеры, endian, значения reserved, идентификаторы, service/ack/block, request/response correspondence, поля ошибок и правила возврата.
3. **Точную модель команд и адресации:** разрешённые *read-only* команды, instance/class/attribute, единицы адресации и упаковку битов для конкретного диапазона памяти.
4. **Контроллерозависимые адреса:** сопоставление CIO `#XXXXX`, логических групп и фактических ответов через проверенную таблицу семейства (см. [typed_memory_model.md](typed_memory_model.md)).
5. **Надёжность:** таймауты, повтор запросов, дедупликацию ответов, sequence IDs, обработку неполных/ошибочных пакетов, лимиты опроса, состояние UNKNOWN при недоступном сигнале.
6. **Изоляцию от записи:** отдельный, по коду ограниченный read-only интерфейс; ни одна операция чтения не должна иметь неявных команд записи или управления сервоприводами.
7. **Эксплуатационную безопасность:** сетевые сегменты, контролируемые частоты запросов, отсутствие воздействия на штатную автоматику, разрешение изготовителя/предприятия.

Факт, что встречаются поля `YERC` или порт `8040` в примерах сторонних источников, **не подтверждает** корректность конкретного сообщения MLAD. Сначала нужен оригинальный manual соответствующего варианта опции с полной командной таблицей и подтверждённые дампы запросов/ответов.

## 3. Контракт будущей реализации (проект, НЕ текущая функция)

```text
Explicit ControllerProfile + verified HSES option/firmware
    → ReadOnlyTransport
       → Validated request encoder (known command + allowed input operands)
       → Response parser (length, IDs, reserved/status, offsets, CRC if applicable)
       → Bounded scheduler / timeout / retry
       → SignalSnapshot(value | UNKNOWN, timestamp, quality, provenance)
       → Separate UI label: LIVE / STALE / DISCONNECTED
```

**Никакого LIVE-индикатора**, пока не проверены источник, свежесть и связь ответа с запросом. **FALSE нельзя подставлять вместо UNKNOWN** по таймауту. Логическое состояние катушки требует отдельной модели вычисления и не тождественно её реальному выходному feedback.

Кодировщик и декодировщик сначала тестируются на **offline golden packets**: положительные случаи, отрицательные status/error, truncated packets, reordered responses, отключение/повтор. Только затем — ограниченные read-only испытания на утверждённом стенде.

## 4. Критерий разрешения read-only мониторинга

Gate H0: первичный документ Yaskawa + firmware/option профиль и разрешённый перечень read-команд.  
Gate H1: тестовый parser/encoder на сохранённых пакетах и строгие ошибки формата.  
Gate H2: подтверждение карт I/O и правильного отображения битов от внешнего эталона.  
Gate H3: лабораторный стресс-тест таймаутов, дисконнекта, повторного соединения и задержек с отказобезопасным UNKNOWN.  
Gate H4: независимая оценка кода, безопасности и разрешение владельца проекта.

**Даже завершённый read-only HSES не разрешает FTP upload, запись регистров, управление роботом или редактирование System Ladder.**
