> **Статус и применимость:** этот документ описывает соответствующее функциональное подмножество и доказательства, собранные до/по PR #21; он **не** означает, что весь проект остановился на PR #21. ## Первоисточники и ограничения доступа

1. [YRC1000 Concurrent I/O R12, OEM-индекс](https://knowledge.motoman.com/hc/en-us/articles/40670912825362-YRC1000-OPTIONS-INSTRUCTIONS-FOR-CONCURRENT-I-O-R12), документ 178648-1CD. Прямая загрузка PDF OEM не удалась (HTTP 403); полнотекстовые таблицы сверены по [воспроизведению YRC1000 manual](https://manualzz.com/doc/84663174/yaskawa-motoman-yrc1000-owner-s-manual) §12.2.17 ADD (стр. 12-18), §12.2.18 SUB (12-19), §12.2.24 MOV (12-25), §12.2.29 SHL (12-30), §12.2.30 SHR (12-31), §12.3 (12-36).
2. [DX100 Concurrent I/O, RE-CKI-A453, Rev.0 / 155491-1CD, PDF](https://gab.wallawalla.edu/~ralph.stirling/classes/engr480/docs/Motoman/dx100_concurrent_io_155491-1CD.0.pdf): соответствующие разделы §12.2/§12.3 подтверждают схожую общую модель. Конкретные контроллеры и прошивки не проверены.
3. DX200 RE-CKI-A465: остаётся самостоятельным документальным gate, не переносить правила поколений молча. Сопоставление форм см. [предыдущее исследование](typed_opcode_grammar.ru.md).

Маркировка: **Manual** — прямое указание в руководстве; **Derived** — вычисленное следствие документированной формулы; **Unknown** — нет однозначной информации; **Bench** — контроллерная проверка (пока отсутствует).

## Таблица пяти команд

| Opcode | Условие ON / результат (Manual) | Carry / Zero / Error (Manual) | Unknown |
| --- | --- | --- | --- |
| MOV S,D | При EN=ON значение S передаётся D; D = M000–M599 / byte / word, S = M000–M999 / 0–65535 / byte / word | Carry изменяется при передаче в байт; текст порога: «больше 256 (BCD)». Zero/Error не используются (0). | Поведение при ровно 256; точное усечение byte |

| SHR S,n,D | Сдвиг 16-битного S вправо, n=0..16, ввод нулей сверху | Carry — вытесняемый LSB. Zero/Error не используются (0) | Carry n=0/16, byte-результат |

### Выполнение / флаги в скане

§12.3 YRC1000: **#51400 Carry, #51401 Zero, #51402 Error**. Перед выполнением Ladder каждого скана флаги очищаются; инструкция, влияющая на флаг, обновляет его по результату при истинном EN, при ложном EN очищает соответствующий флаг; другая инструкция, не влияющая на данный флаг, его не изменяет.

SHL/SHR при EN=ON исполняются **каждый скан**; для одиночного действия руководство рекомендует использовать PLS/PLF в условии. Для всех пяти ON — обязательное условие выполнения. Условия самой реальной цепи и порядок исполнения нескольких команд MLAD пока не подтверждает.

Глобально запрещать повторные назначения в M было бы ошибкой: §12.2 допускает многократные назначения регистров арифметических инструкций, но запрещает многократный выход на текущие регистры TMR/CNT. Дублирование конкретных реле также имеет ограничения.

### Критические граничные случаи

- MOV→byte при S=256. Слова руководства «more than 256 (BCD)» не разрешают автоматически использовать общую PLC-эвристику «>255». Модель возвращает Unknown для byte-значений от 256; проверка реального усечения и флага отложена.
- SHL/SHR при n=0: математический результат S, но Carry не определён моделью (нет вытесненного бита). При n=16: 16-битный результат 0, но Carry и специфика byte остаются Unknown. Неверное использование Rust `wrapping_shl(16)` превратило бы сдвиг в сдвиг на 0, поэтому ветка 16 обработана отдельно.
- EN=OFF: результат `NotExecuted`; флаги в отдельной модели оставлены `Unresolved`. §12.3 описывает clearing в скане, но полной модели взаимодействия инструкций нет.
- Отдельно не решены byte/word aliasing, конкретная версия прошивки и конфликт повторных M-назначений.

## Автономная реализация

`src-tauri/src/compiler/reference_semantics.rs` — изолированная чистая функция `evaluate_reference(ReferenceInput)`. Не читает `CIOPRG.LST`, не выполняет Ladder и не подключена к Tauri IPC. Все результаты помечены `ManualDerived`, `Unresolved` либо `NotExecuted`. Флаги `controller_execution_verified=false`, `scan_chain_verified=false`, `native_write_allowed=false` независимо от исходных данных.

Тесты: шесть классов арифметического carry/borrow/zero, полный перебор 65536 значений ADD/SUB со вторым операндом 1, MOV byte 255/256/257, SHL/SHR 0/1/16/17, EN On/Off/Unknown, неподходящее назначение. Никакие реальные программы роботов не включены в тесты.

В Native Workspace справочник по выбранной команде показывает формат, правила, ограничения и неизвестные зоны. **Не** показывает «фактически вычисленный» результат реальной строки CIO.
