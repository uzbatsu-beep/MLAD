# Кодекс взаимодействия участников MLAD

**Дата:** 18.11.2026. Применяется к GitHub Issues, Pull Requests, Discussions, code review и иным площадкам, где участники представляют MLAD.

## Наша цель

MLAD создаётся для ответственного инженерного исследования промышленной автоматизации. Приветствуются техническая критика, воспроизводимые тесты, документация и корректное обсуждение ограничений. Разногласие по архитектуре или интерпретации руководств — нормальная часть работы; переход на личности недопустим.

## Ожидаемое поведение

- Разделяйте **наблюдение**, **гипотезу**, **утверждение из документации** и **результат проверки на контроллере**. Не называйте неоттестированную семантику «достоверной».
- Общайтесь уважительно и по делу независимо от опыта, роли, языка и происхождения участника; приводите технические доводы вместо обвинений.
- Признавайте возможные ошибки, исправляйте неточности, указывайте ссылки на доступные разрешённые источники и фиксируйте границы проверки.
- Соблюдайте права владельцев программ, документации, промышленных данных и сторонних библиотек.
- Передавайте сообщения об уязвимостях по [SECURITY.md](SECURITY.md), не публикуйте эксплойты и данные роботизированных ячеек в общедоступных обсуждениях.

## Недопустимое поведение

Преследование, угрозы, оскорбления, дискриминация, публикация чужих конфиденциальных данных, попытки выдать себя за представителей производителя, заведомое введение в заблуждение о безопасности, навязывание действий с оборудованием без согласования. Также запрещены повторяющийся спам и вмешательство в обсуждения с целью блокировать ответственную разработку.

## Сообщение о нарушениях и реакция

При нарушении используйте доступный **приватный канал связи с сопровождающим через GitHub, если он настроен**, либо встроенную возможность **Report content** платформы. В публичных Issues допустимо описывать только общую проблему модерации **без персональных, конфиденциальных или опасных деталей**. **Публичного адреса электронной почты для сообщений здесь не назначено.**

Сопровождающий оценивает обстоятельства и соразмерность мер: просьба скорректировать сообщение, предупреждение, скрытие/удаление контента, ограничение участия либо блокировка. По возможности сохраняется приватность заявителя и сторон; абсолютная конфиденциальность не гарантируется. Вопрос пересмотра решения можно поднять через доступный приватный канал GitHub; немедленной реакции или установленного SLA не обещается.
