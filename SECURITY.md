# Политика безопасности MLAD (Security Policy)

**Дата введения:** 18.11.2026. **Область:** открытый репозиторий MLAD и его опубликованные инженерные preview-сборки.

> MLAD — экспериментальный OFFLINE/BENCH-инструмент для анализа Yaskawa Concurrent I/O. **Не использовать как доказанный компилятор, устройство безопасности, инструмент эксплуатации робота или источник live I/O.** Ни один режим не разрешает загрузку программ в робот или изменение оригинальных CIOPRG.LST/IONAME.DAT.

## Поддерживаемые версии и исправления

| Компонент | Политика |
| --- | --- |
| Актуальный `main` | Принимаются сообщения и исправления; сроки реакции и выпуска исправления не гарантируются |
| Последний Windows pre-release (на дату политики: `v0.5.0-rc.9-oem-reference`) | Принимаются сообщения; версия экспериментальная, **не сертифицирована как безопасная для оборудования** |
| Старые RC и отдельные архивные ветки | Не поддерживаются как отдельные линии исправлений; рекомендуется сверять дефект с актуальным `main` |

Эта таблица **не является обещанием обслуживания по SLA**. Статус конкретной версии сверяйте по [GitHub Releases](https://github.com/uzbatsu-beep/MLAD/releases) и [актуальной матрице проекта](docs/project_status.md).

## Как сообщить об уязвимости

**Не создавайте публичный Issue с техническими подробностями ещё не устранённой уязвимости.**

1. Откройте вкладку **Security** репозитория и проверьте, доступна ли кнопка **Report a vulnerability**. Если доступна, отправьте описание через **GitHub private vulnerability reporting**. Возможность зависит от настроек репозитория и не гарантируется наличием одного только `SECURITY.md`.
2. Если функция недоступна, создайте **обычный публичный Issue без деталей уязвимости**, только с запросом к сопровождающему определить безопасный приватный канал для координации. **Не** прикладывайте PoC, пути, токены, содержимое файлов, конфигурации сети или воспроизводящий эксплойт. Используйте затем согласованный закрытый канал.
3. Если нарушение относится к злоупотреблениям на самой платформе GitHub, используйте механизмы **Report** GitHub; они не заменяют технический канал для уязвимостей MLAD.

**Не выдуман и не опубликован адрес электронной почты сопровождения; наличие приватного канала проверяется отдельно.** Инструкция по включению private vulnerability reporting: [GitHub Docs](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).

При закрытом сообщении полезно описать: версию MLAD/commit, операционную систему, ожидаемую и фактическую границу безопасности, минимальное **синтетическое** воспроизведение, степень влияния и затронутые файлы/компоненты. Не прикладывайте настоящие файлы роботов.

## Конфиденциальность промышленных данных

**Запрещено публиковать в GitHub Issues/PR/Actions/коммитах:**

- реальные `CIOPRG.LST`, `IONAME.DAT`, резервные копии системного ПО, карты I/O и параметры производственных роботов без права на раскрытие;
- реальные IP-адреса, сетевые топологии, credentials, ключи доступа, сеансовые токены и журналы с ними;
- личные/коммерческие данные организации и сведения, позволяющие восстановить эксплуатационные цепи без разрешения владельца.

Перед публикацией заменяйте любые данные **самостоятельно созданными синтетическими примерами**. Простое удаление имени предприятия не гарантирует обезличивания логики и адресов. Хэш реального исходника, путь к файлу, имя узла и версия прошивки тоже могут раскрывать контекст; публикуйте их только при наличии разрешения.

## Границы доверия проекта

- `CIOPRG.LST` и `IONAME.DAT` — только чтение; JSON drafts — отдельный формат. Оригинальные файлы нельзя изменять или пересобирать как native-программы.
- FTP/HSES, мониторинг, live I/O, деплой и команды записи в робот **отключены**.
- `TRUE/FALSE/UNKNOWN` в локальных моделях — **не** живые сигналы контроллера.
- `MOV/ADD/SUB/SHL/SHR`: `TypedCandidate`, статические ссылки и `ManualDerived` **не** равны результатам исполнения на конкретной системе.
- В текущем `main` PR #25–#26 добавили CSP/path guard/identity-checked reads, PR #28 — Windows NTFS security CI, PR #29 — сравнение File ID+bytes, отказ от hardlinks/ADS/UNC/device paths и staged SHA-256 checks. **Открыты:** финальное `check→rename` TOCTOU, ancestor races, Windows ACL, транзакция `backup+target`, power-loss durability и ручной Windows/WebView2 smoke. CI **не** является независимым pentest; [модель угроз](docs/filesystem_security_pr29.md).

Проверяйте экспериментальное ПО только автономно на копиях, **без подключения к действующему промышленному оборудованию**. Не исследуйте уязвимости на чужом контроллере, предприятии или сети без явного разрешения.

## Дополнение к конфиденциальности и управлению PR (21.11.2026)

Последний Windows pre-release — `v0.5.0-rc.10-unified-offline`, а не rc.9. Старые указания релизов и baselines выше относятся к собственным датам. `UserSmoke=NOT RUN`, `OEMBench=NOT RUN` не подтверждены отдельно; подробности — [аудит Git](docs/repository_audit_2026-11-21.md).

Локальные `*.mlad.json` sidecar и `*.mladproj.json` manifests могут раскрывать **конфиденциальную** информацию даже без сырых байтов `CIOPRG.LST` и `IONAME.DAT`: комментарии, относительные пути и SHA-256 способны идентифицировать инженерную среду. `.gitignore` защищает лишь от случайной индексации новых файлов, но не очищает уже отслеживаемые данные. `HSES`/`FTP`, native writer и robot deployment остаются `BLOCKED`. Защита ветки `main` сейчас требует `frontend-build`, но не обязательного `ci-gate`; Ruleset изменяет только владелец после согласования.
