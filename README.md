# Next-Gen Yaskawa Motoman Ladder IDE

Современная интегрированная среда разработки (IDE) с открытым исходным кодом для создания, редактирования, валидации и онлайн-мониторинга параллельного ввода-вывода (**Concurrent I/O**) промышленных роботов Yaskawa Motoman. Проект нацелен на замену устаревшего проприетарного ПО более производительным, расширяемым и удобным инструментом.

## 🚀 Технологический стек

*   **Frontend (Интерфейс):** Tauri v2, TypeScript, Vite, React (или Svelte) для построения реактивного UI.
*   **Редактор графов:** React Flow / Svelte Flow для реализации бесконечного адаптивного холста релейных схем.
*   **Backend (Системная логика):** Rust. Обеспечивает высокую скорость компиляции, безопасность работы с памятью и многопоточность.
*   **Сетевой уровень:** Асинхронная среда `tokio` (Rust), библиотеки `suppftp` для деплоя файлов и кастомная реализация UDP/TCP пакетов для работы с протоколом High-Speed Ethernet (HSE) Yaskawa.

## 🛠 Ключевые архитектурные отличия

1.  **Git-friendly формат хранения:** Вместо закрытых бинарных файлов проекта (`.LAD`) среда использует человекочитаемый формат JSON/YAML для хранения исходного кода схем. Это позволяет полноценно использовать системы контроля версий и просматривать diff изменений.
2.  **Отсутствие жесткой сетки:** Свободное масштабирование, группировка цепей (Rungs), добавление текстовых заметок прямо на холст и неограниченное количество столбцов логических элементов.
3.  **Безопасный компилятор:** Встроенный статический анализатор на Rust проверяет логику «на лету» до загрузки в робота. Он выявляет гонки сигналов, дублирование катушек (Double Coil Access) и логические тупики.
4.  **Кроссплатформенность:** Полноценная поддержка Windows, Linux и macOS благодаря возможностям Tauri.

## 📜 Правила разработки и кодирования

*   **Фронтенд:** Строгая типизация TypeScript. Компоненты логических блоков должны быть атомарными. Данные холста синхронизируются с бэкендом через оптимизированные вызовы Tauri IPC (команды и события).
*   **Бэкенд:** Код на Rust должен быть максимально идиоматичным. Логика парсинга выносится в чистые функции без побочных эффектов. Все сетевые операции ввода-вывода обязаны быть асинхронными (`async/await`).
*   **Документирование:** Каждая новая инструкция или функция компилятора должна сопровождаться ссылкой на стандарты Concurrent I/O Yaskawa.

## 🎯 План реализации (Этапы)

*   [ ] **Этап 1:** Базовая структура проекта, конфигурация Tauri, архитектура JSON-формата схем.
*   [ ] **Этап 2:** Фронтенд-редактор: холст, добавление контактов (NO/NC), катушек (OUT), таймеров и счетчиков.
*   [ ] **Этап 3:** Бэкенд-компилятор: генерация валидного текстового файла инструкций (`.LST`) из JSON-модели холста. Парсер существующих `.LST` файлов.
*   [ ] **Этап 4:** Сетевой модуль: автоматизация бэкапов и загрузки через FTP, реализация онлайн-инспектора сигналов через HSE протокол.
